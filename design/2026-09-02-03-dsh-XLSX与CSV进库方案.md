# XLSX / CSV 进库：转 UTF-8 CSV，让检索能读懂

> 日期：2026-09-02  
> 序号：03（02 是预览分区；本档是表格进库实现方案）
> 修订：2026-09-03 — 明确 M0 CSV 基础集成与 M1 转码/XLSX/列名 excerpt 的边界，统一 preview payload 和原子写入契约。
> 定位：最终目标是把 `.xlsx` 或 Excel 默认另存的 `.csv` 统一落成 **UTF-8 CSV**；当前 M0 先接入已经是 UTF-8 的 CSV，M1 再做转码、XLSX 和列名 excerpt。
> 对照：[01 DOCX](./2026-09-01-01-dsh-DOCX转Markdown方案.md)、当前 `ingest.ts` / `search.ts`。
> 不改：工具名、先选库再搜、不新增 `kb_read`、不装 `xlsx@0.18.5`。
> 性质：实现方案。写代码前对照本档；**未跑真实台账，不声称验收通过**。

> 当前里程碑：本档是 M0/M1 总方案；当前实现先按 [04 CSV M0](./2026-09-02-04-dsh-CSV基础导入与展示方案.md) 落地 M0。M0 只支持 UTF-8 CSV 原字节复制与只读展示，不启用 XLSX、GB18030/UTF-16 转码或 Converter registry。本文中标注为 M1 的内容不得在 M0 的 UI、工具描述或验收结果中宣称已支持。

> 结构更新：2026-09-03 起，M0 使用按文件类型组织的 Content Registry。`SourceFormat` 负责导入源（markdown / plain-text / csv / 未来 xlsx），`EntryFormat` 负责库内条目（markdown / csv）。`src/content/host-api.ts` 是导入、读取、搜索与写入的 Host 唯一入口；Client 通过 `src/content/client-api.tsx` 按 Host 回传的格式渲染。后续实现以 [内容处理目录方案](./2026-09-03-01-dsh-格式路由重构简版.md) 和 04 档为准；本文旧的 `TEXT_EXTS` / `SEARCH_GLOBS` 表述仅保留改造前背景。

> 术语核对：CSV 不是“任何格式”的通用容器；至少还要区分字符编码、分隔符、引号规则和是否允许跨行字段。当前 M0 只做 UTF-8 编码门禁，不做方言转换。M1 若要兑现“输入常见 CSV 后转成我们定义的 CSV”，必须另行固定输入范围与规范输出，不能只把 `TextDecoder` 换成多种编码就宣称完成。

## 1. 一句话

不要「只把 `.csv` 加进白名单再 `copyFile`」。中文 Excel 默认 CSV 经常是 GBK，原样拷进库后 ripgrep 当二进制跳过或乱码，模型等于没读到。

本档分两个阶段，不把未完成的转换能力提前暴露：

1. **M0：CSV 基础集成**：只接受严格 UTF-8（有无 BOM）的 `.csv`，单文件有效上限为 `min(prefs.maxFileBytes, 20 MiB)`，以一次性已校验的原始 Buffer 原子写入，保持原始字节；库树、篇数、去重、原始物理行搜索和只读纯文本预览全部可用。详见 04 档。
2. **M1：CSV 规范化 + XLSX**：`.csv` 做受控编码解码并写成 UTF-8+BOM；`.xlsx` 在依赖来源门禁通过后，用 SheetJS-compatible 库的 `XLSX.read(buffer)` + `sheet_to_csv` 输出一个或多个 CSV。CSV 不调用 `XLSX.read`。
3. **M1 检索增强**：CSV 命中按 RFC 4180 解析为逻辑记录，保留物理行号，按列名生成 excerpt。M0 不做记录级解析和列名化。

库内正文就是 CSV。不转 Markdown。

## 2. 为什么不能只放行后缀

| 只改 `TEXT_EXTS` | 实际后果 |
|------------------|----------|
| ingest `copyFile` | GBK 原样进库 |
| `search.ts` glob 仍是 `*.md` `*.txt` `*.markdown` | 就算进了也 **0 命中** |
| 即使补上 `*.csv` | 非 UTF-8 被 rg 当二进制跳过；`readFile(..., 'utf8')` 拼 excerpt 乱码 |
| excerpt 是生 CSV | 命中在第 80 行时没有表头，模型看见 `甲,120000` 不知道列名 |

AI 没有读整篇的工具，只能吃 excerpt。所以「能读懂」必须在 **落盘编码** 和 **截段改写** 两处保证，不能靠用户手选 UTF-8。

做得到的：「甲公司金额多少」→ excerpt 里有 `供应商: 甲公司 | 金额: 120000`。  
做不到的：对 2000 行求和、透视。那是换档（`kb_read` / 按行切），本档不写。

## 3. 管道

```
.xlsx（M1，只读）                          .csv（M0 UTF-8；M1 可转码，只读）
        │                                               │
        ▼                                               ▼
 M1 XLSX.read(buf, { type: 'buffer' })        M0 严格 UTF-8；M1 侦测编码 → TextDecoder
        │                                               │
        ▼                                               │
 先作范围/公式预检；每个可导出 sheet：sheet_to_csv(...)       │
        │                                               │
        └───────────────┬───────────────────────────────┘
                        ▼
       M0：写入同一份已校验原始 Buffer
       M1：前面加上 UTF-8 BOM（EF BB BF）写出
                        ▼
              bases/<id>/<类目>/<名>.csv
                        ▼
       M0：指纹 / 冲突 / 配额对象是原始 UTF-8 Buffer
       M1：指纹 / 冲突 / 配额对象是规范化后的 UTF-8 Buffer
                        ▼
        kb_search：glob 含 *.csv
        M1 拼 excerpt 时按表头改写成「列名: 值」（不要再 XLSX.read）
```

两条源在「统一输出 Buffer」阶段汇合，**不在 `XLSX.read` 汇合**：M0 原样复用已校验 Buffer，M1 才按规范输出（包括是否加 BOM）。`sheet_to_csv` 返回 JS 字符串、不带 BOM。xlsx 不要做 GBK 猜测（OOXML 已是 Unicode）。

| 决策 | 取舍 |
|------|------|
| M0 库里不留 `.xlsx` | 与 DOCX 档一致；grep 只扫文本 |
| M0 `.csv` 不直接 `copyFile` | 先读入、严格校验并复用同一 Buffer 原子写出，避免校验后源文件变化 |
| M1 `.csv` 不 `copyFile` | 必须转码再写出，否则 GBK 漏网；**不解析、不改格子** |
| 一本工作簿多表 | 每表一个文件：单表用 `原名.csv`；多表用 `原名-表名.csv` |
| 指纹哈希 | M0 对已校验的原始 UTF-8 Buffer；M1 对写出后的规范化 UTF-8 Buffer；同一份 GBK 与 UTF-8 源在 M1 可归一 |
| 公式 | 只要缓存计算结果 |
| 图 / 宏 / 透视布局 | 丢掉 |
| 隐藏 sheet / 行 / 列 | 默认不进库并给 warning，避免把用户故意隐藏的数据变成可检索正文 |

md / txt / markdown 仍 `copyFile`，本档不动。

## 4. 库内 CSV 长什么样

M0 保留源文件的 BOM 与换行；M1 的转换产物统一写 UTF-8 BOM（`EF BB BF`）。两种形态都必须在读回和展示时剥掉 BOM。

- 从 **xlsx** 来的：`sheet_to_csv` 出逗号分隔、`\n` 换行，字段按库的规则加引号。  
- 从 **csv** 来的：M0 正文与源一致（含分号分隔、原引号）；M1 当前只规划编码与换行归一，不重排列、不改 `00123` / 日期 / `=公式`。这叫“编码归一”，不等于把任意 CSV 方言转成统一逗号 CSV。

如果产品目标确实是“常见 CSV 输入 → 知源定义的规范 CSV”，M1 实现前还必须补齐以下契约：

1. **输入编码**：至少明确 UTF-8（有无 BOM）、UTF-16 LE/BE（有 BOM）和 GB18030/GBK 是否接受；无 BOM 的遗留编码不能无提示地猜测，必要时给出 `encoding_assumed` warning 或要求用户选择。
2. **输入方言**：明确支持逗号、分号、Tab 哪些分隔符；使用 RFC 4180 状态机处理引号、`""`、引号内分隔符和跨行字段；畸形引号必须逐文件失败，不能静默拆列。
3. **规范输出**：建议固定为 UTF-8+BOM、逗号分隔、按需加双引号、LF 换行；保留字段值和空列，不执行 `=HYPERLINK(...)` 等公式文本，不改变 `00123` / 日期字符串。
4. **边界与指纹**：解析前后分别检查源体积、输出体积和单源总量；哈希、配额和落盘都针对最终规范输出 Buffer，转换失败不写入任何输出。

在这组契约落地前，M1 只能称为“受控编码归一”，不能称为“任意 CSV 格式转换”。

```csv
供应商,金额,币种
甲公司,120000,CNY
乙公司,98000,CNY
```

读回时 **必须剥掉 BOM**，否则第一列表头变成 `\uFEFF供应商`，改写 excerpt 会对不上。M0 的预览和搜索也必须走严格 UTF-8 读取，不能用会替换坏字节的 `readFile(..., 'utf8')` 作为安全校验。

空表、全空 sheet：跳过，不写文件，warnings 记一句。  
隐藏或 VeryHidden sheet：默认跳过，不写文件，warnings 记一句。可见 sheet 的隐藏行/列也默认跳过；读取时开启库要求的行列元数据选项，并在 `sheet_to_csv` 传 `skipHidden: true`。第一版不提供“导入隐藏数据”的 UI 开关。若所有 sheet 都因此跳过，源级结果为 `skipped`（不是成功的零输出），同时带稳定 warning。

硬上限（防一张表撑爆 5 MB / 拖垮进程）：

| 上限 | 值 | 超了 |
|------|----|------|
| 工作表 | 32 | 整份工作簿失败，不落盘 |
| 单表 `!ref` 声明行数 | 2000 | 整份工作簿失败，不落盘 |
| 单表 `!ref` 声明列数 | 40 | 整份工作簿失败，不落盘 |
| 单源转换产物合计 | 20 MB | 整份工作簿失败，不落盘 |
| 转换墙钟 | 30s | 该项失败 |
| 源体积 / 写出体积 | `maxFileBytes` 各过一遍 | 该项失败 |

不能把“超过上限”实现为截断后成功：那会使模型检索到一份看似完整、实际缺尾部数据的台账。转换子进程必须在调用 `sheet_to_csv` 前以 `!ref` 解出的**原始声明范围**检查 workbook / worksheet（不因隐藏行列放宽）；超限则返回结构化失败，避免稀疏范围在导出时被遍历。Host 在 30s 后强制终止子进程，限制 IPC 合计为 20 MB；Node 的 V8 堆限制不覆盖外部 Buffer，故不能以 `Promise.race` 或 Worker 堆限制冒充内存沙箱。

## 5. 模型怎么「读懂」：只改 excerpt，不改工具（M1）

`kb_search` 契约不变：`path` / 行号 / `excerpt`。Skill 仍禁止用项目 `read` 冒充知识库。

M0 只保留 ripgrep 的原始物理行 excerpt；M1 才在生成 excerpt **之前**解析整份至多 5 MB 的规范化 UTF-8 文本，并在一次搜索中按文件缓存解析结果。CSV 不能在 clip **之后**按行拆字段：合法 CSV 允许引号中的逗号、分号、双引号和换行。

1. 剥 BOM；使用自有、小型 RFC 4180 状态机，支持 `""`、引号中的分隔符与换行，并产出每条记录的物理起止行。**不要** `XLSX.read` 库内 csv，避免 `ID,` 走 SYLK、日期被改成序列。
2. CSV 没有自描述分隔符：扫描首条非空逻辑 record 的**引号外**逗号 / 分号数；仅一个候选出现时选择它，两个都出现或数量相同则 `csv_parse_fallback`。两者均未出现时按单列 CSV 处理（逗号与分号结果相同）。选定后全文件固定；无法一致解析时保留原始 excerpt，不得猜字段。
3. `rg` 命中物理行后，以该行所属的逻辑记录为中心取前后各 8 条记录；`startLine` / `endLine` 仍回传原文件物理行号。
4. excerpt **第一行固定插入** `列: 表头1 | 表头2 | …`。字段中的换行显示为 `↩`，不改变库内原 CSV。
5. 表头行自己被命中时，只保留 `列: …`，不要扩成 `供应商: 供应商`；字段数不一致时，缺的当空、多的标 `列N`。

模型实际看到的（命中第 3 行「乙公司」）：

```text
列: 供应商 | 金额 | 币种
供应商: 甲公司 | 金额: 120000 | 币种: CNY
供应商: 乙公司 | 金额: 98000 | 币种: CNY
```

工作台预览仍显示库里的生 CSV，不走这套改写。对话命中卡用改写后的 excerpt。

不要为了可读再落一份 `.md`。双份会重复命中、指纹乱。

## 6. 编码：把「请另存 UTF-8」做成 Host 的事（M1）

M0 仅接受严格 UTF-8，不猜测编码；M1 才按字节侦测并规范化。无论哪个阶段，校验过的内容都必须与最终写出的内容是同一份 Buffer，不能“校验一次、再 `copyFile` 源文件”。

| 优先级 | 判定 | 解码 |
|--------|------|------|
| 1 | `EF BB BF` | UTF-8，去掉 BOM |
| 2 | `FF FE` / `FE FF` | UTF-16 LE / BE |
| 3 | 整份是合法 UTF-8（允许裸 UTF-8 无 BOM） | UTF-8 |
| 4 | 否则 | 明确标记为“假定 GB18030”的严格解码 |

Node 自带 `TextDecoder`，不要加 `iconv-lite` / `papaparse`。UTF-8、UTF-16 和 GB18030 一律使用 `{ fatal: true }`，避免替换字符掩盖损坏。Host 启动或首次转换时要探测 `gb18030` 是否可用：Node 的 small-ICU 构建可能不支持它，届时返回 `encoding_unsupported`，不能静默降级。第 4 步不是通用“侦测”：它只适合本产品的中国 Excel 范围，必须附 `encoding_assumed_gb18030` warning；其他遗留编码以后用用户明确选择的扩展，不可猜测。

解码后拒绝 NUL，控制字符只允许 tab 与换行，确保 ripgrep 不会把库内 CSV 当二进制。通过后才加 BOM 写出，换行 `\r\n` / `\r` 收成 `\n`：

```ts
const text = decodeCsvBytes(buf).replace(/\r\n|\r/g, '\n')
const utf8 = Buffer.concat([Buffer.from([0xef, 0xbb, 0xbf]), Buffer.from(text, 'utf8')])
```

不要 `XLSX.read(decodedText, { type: 'string' })`：`read` 会按首字节猜 SYLK / HTML / DIF，默认还把 `00123`、日期、`=A1` 当 Excel 格子改掉。漏写 `type` 会把整段当 Base64。

Excel 默认 ANSI CSV 在中国常走第 4 步。无法解码、运行时不支持 GB18030、含 NUL/非法控制字符或解出空文件：该项 `failed`，返回稳定错误码及通用文案，不回显原始异常。

## 7. XLSX 库只用于 xlsx（M1）

xlsx → CSV 用 SheetJS 的 `sheet_to_csv`。公共 npm 上的 `xlsx@0.18.5` 有已知安全问题，**禁止 `npm i xlsx`**。csv 源不进这个库。

| | 决定 |
|--|------|
| 选库门禁 | 方案原称 `@stackline/xlsx` 为“CE 0.20.3”，但当前 npm 包版本为 1.0.5，不能据此推断来源或安全性。接入前必须核验源码仓库、固定 commit、发布者、tarball integrity、许可、依赖树与审计结果；未通过前不得装入运行时依赖 |
| 候选 | `@e965/xlsx@0.20.3` 有公开自动发布来源和内置类型，但同样属于第三方再发布；是否采用也须过上列门禁，不能作为未经审计的自动回退 |
| 读 xlsx | `XLSX.read(buf, { type: 'buffer', cellDates: false, cellStyles: true })`；不计算公式。若可导出单元格带 `f` 且没有 `v` 自有属性，则整份源失败，提示用户在 Excel 重新计算并保存；不能用 `if (!cell.v)` 误判 `0` / 空字符串。缓存可能过期，程序无法证明其新鲜度，产品文案需要求用户计算并保存 |
| 写出 CSV | 先验证 `!ref` 声明范围未超过硬上限，再 `XLSX.utils.sheet_to_csv(ws, { FS: ',', RS: '\n', blankrows: false, skipHidden: true })` |
| 读用户 csv | **不调用**。§6 转码 + BOM |
| BOM | 库不写；两条源都是我们 `Buffer.concat([BOM, Buffer.from(text, 'utf8')])` |

不要装：`node-xlsx`、`exceljs`、各种 `xlsx-to-csv`、officeparser / markitdown-ts / Python。

`.xls` / `.xlsm` / 加密工作簿：失败，提示另存为未加密 `.xlsx`。第一版不要开 SheetJS 的 `.xls` 路径。

## 8. 模块怎么切（≤300 行；M1 扩展点）

入口只装配。新逻辑不要堆进 `ingest.ts` / `search.ts`。

| 文件 | 职责 |
|------|------|
| `src/convert/registry.ts` / `run-isolated.ts` | M1 与 DOCX 共用的受信任 descriptor、子进程生命周期和限长 IPC；`CONVERT_EXTS` 唯一来源。M0 不注册 CSV converter |
| `src/identity.ts` | `TEXT_EXTS` **加上 `.csv`**（库内可检索 / 计数 / 树）；`SEARCH_GLOBS` 从 `TEXT_EXTS` 派生，禁止再手写三份 glob |
| `src/convert/csv/encoding.ts` / `worker.ts` | M0 共用一次性 Buffer 与严格 UTF-8 校验；M1 增加编码解码、换行归一与 BOM（恒一 output，不 import SheetJS） |
| `src/convert/xlsx/sheet-to-csv.ts` | **唯一调用 XLSX 库的地方**：先检查 sheet 数 / `!ref` 声明范围 / 公式缓存，再输出 UTF-8+BOM Buffer |
| `src/convert/xlsx/worker.ts` | 读 Buffer → XLSX 库 → `sheet-to-csv`；多表拆文件名；仅此处 import XLSX 库 |
| `src/ingest-output.ts` | copy 与 convert 共用的输出名复验、哈希、配额预检、临时写入 / 回滚 |
| `src/ingest.ts` | 遍历、copy 与 convert 分叉、源级结果聚合；不 import XLSX 库 |
| `src/search-csv.ts` | RFC 4180 记录解析、行号映射、列名 excerpt；不属于 Converter |
| `src/search.ts` | M0 使用 `SEARCH_GLOBS`、大小写不敏感 glob 与原始物理行 excerpt；M1 再分派给 `search-csv.ts` |
| `src/entry-preview.ts` | M0/M1 共用 `readEntryPreview`、固定 view、严格读取、窗口与 CSV 只读策略；从 `bases.ts` 拆出避免超 300 行 |
| `src/pick-source.ts` | M0 加 `*.csv`；M1 再加 `*.xlsx` |
| `src/client/settings/PrefsPage.tsx` | M0 只勾上「CSV（UTF-8，只读）」；M1 再勾上 XLSX |
| `src/client/settings/AdditionalDialogs.tsx` | M0 只写 UTF-8 CSV；M1 再补 docx/xlsx 转换文案 |
| `src/tools.ts` / `src/skill.ts` | M0 描述 UTF-8 CSV；M1 再补 csv/xlsx 自动转码 |

`TEXT_EXTS` 加 `.csv` 之后，`bases.ts` 扫篇数、列树、已有哈希扫描会自动带上，不必再改一遍。M1 的 `CONVERT_EXTS` 不在 M0 提前引入；启用 registry 后统一从 `convert/registry.ts` 派生。

`ingest.ts` 失败文案不要写死三种后缀。M0 根据 `TEXT_EXTS` 拼；M1 启用 registry 后再合并 `CONVERT_EXTS`。

建议口（实现时落类型；M1 Converter 使用）：

```ts
type ConvertOutcome = {
  files: { destName: string; bytes: Buffer; warnings: string[] }[]
}

convertXlsx(sourcePath: string): Promise<ConvertOutcome>
convertCsv(sourcePath: string): Promise<ConvertOutcome>  // 恒为 1 个文件，destName 仍是原名.csv
```

`ingestOne` 对 M1 转换源：

1. 源体积 > `maxFileBytes` → 失败。  
2. convert 抛错 → `failed`，返回稳定错误码和通用文案。
3. 每个写出文件：`byteLength` 再过 5 MB / 10 GB。  
4. 目标名：xlsx 去 `.xlsx` 按 §3 规则加 `.csv`；csv 保持 `.csv`。sheet 名先映射成保守的文件名片段（空值回退 `sheet-<序号>`），再由 `ingest-output` 复验 basename 和处理冲突；不得直接把 sheet 名当路径。冲突仍 `name-2.csv`。
5. `sha256` 对写出 Buffer，不是源文件。  
6. `ingest-output.ts` 的临时写入 / rename / 回滚，不 `copyFile` 源。
7. 一本 xlsx 写出多个 csv：每一份单独占一条 output 结果（copied / renamed / skipped）。其中一个超单文件 5 MB、单源合计 20 MB、超库配额或写入失败：**先算总字节再写**，整份 xlsx 失败、不落盘或回滚本次新建输出。

md 混在同一文件夹里：md 照旧拷；xlsx/csv 走转换；失败项不挡同批。

## 9. 各文件改什么（插入点）

只列本档需要动的。预览右侧分区（02）的布局不在范围；CSV 预览组件、统一 Host preview payload 和右侧加载状态属于 M0 的展示集成，不做表格控件。

### 9.1 `src/identity.ts`

现在：

```ts
export const TEXT_EXTS = new Set(['.md', '.txt', '.markdown'])
```

M0 的分叉是：CSV 走一次性 Buffer 校验/原子写入；md/txt/markdown 保持复制；其他后缀逐文件失败。M1 再替换为以下 Converter 分叉：

```ts
export const TEXT_EXTS = new Set(['.md', '.txt', '.markdown', '.csv'])
export const SEARCH_GLOBS = [...TEXT_EXTS].map((ext) => `*${ext}`)
```

M0 不定义 `CONVERT_EXTS`。M1 启用 registry 后，`CONVERT_EXTS` 由受信的 Converter 描述导出；`.csv` 届时同时属于「库内可检索文本」和「导入时需规范化的转换源」，由 `ingest.ts` 优先按 registry 分派，避免直接 copy。

### 9.2 `src/ingest.ts`（约 166–192 行）

现在：非 `TEXT_EXTS` 直接失败，然后 `sha256File` + `copyFile`。

改为：

```
registry 有对应 Converter  → 隔离 convert → `ingest-output` 预检、指纹、临时写入/改名
后缀 ∈ TEXT_EXTS         → 现逻辑（md/txt/markdown）也走 `ingest-output`
否则                     → failed，reason 列出允许的源后缀
```

不要在 `ingestOne` 里 import XLSX 库或写编码。体积：转换前看源，转换后再看 Buffer；一个 xlsx 的多个 CSV 输出必须作为同一源的一笔事务提交或回滚。

### 9.3 `src/search.ts`（约 139、147–159 行）

把手写 glob 换成 `SEARCH_GLOBS`，并固定使用 `--glob-case-insensitive`，保证 `.csv` 与 `.CSV` 行为一致。M0 保持物理行 `clipAround`；M1 才由 `search-csv.ts` 解析整份上限 5 MB 的文件并缓存「逻辑 record ↔ 物理行范围」，再按命中行定位 record、截取前后 8 个 record、补列名。不能先用 `clipAround` 切原始行再猜 CSV 结构。

对外 `startLine` / `endLine` 仍是**文件里的物理行号**（含表头），不要改成「数据行号 - 1」。模型引用路径+行号时，人对着预览能对上原 CSV；字段中的换行在 excerpt 中显示为 `↩`。

## 12. 和 01 档的关系

01 定义通用 Converter、Host-only 与多输出事务；这些规则从 M1 开始启用。M0 不注册 Converter，但仍提前复用其安全原则：Host-only、输入边界、同一 Buffer 校验/写出、原子落盘和错误不回显。M1 的最终形态是：**xlsx → 通过溯源审查且固定版本的 XLSX 库 → UTF-8+BOM CSV**；**csv → 严格转码 + BOM CSV**，不生成 Markdown。

「模型读懂」靠检索改写 excerpt，不靠把表变成 md。以后预览若做表格控件，仍读库里这份 UTF-8 CSV。
