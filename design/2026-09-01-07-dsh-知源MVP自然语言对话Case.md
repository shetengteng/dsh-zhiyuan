## 1. 执行说明

这些 Case 必须在真实 DSH 对话中执行，重点检查工具调用顺序、调用参数和回答出处，不要求回答措辞完全一致。单元测试只能证明 Skill/system prompt 文本契约，不能替代真实模型验收。

每个 Case 的统一操作是：准备前置数据，在 DSH 对话中发送用户输入，记录工具调用和最终回答，再按“通过标准/不通过标准”判定。记录时不要写入 token、账号、个人文件路径或真实文件正文。

## 2. Case 清单

| ID | 自然语言输入 | 前置数据 | 通过标准 | 不通过标准 | 本轮进度 |
| --- | --- | --- | --- | --- | --- |
| NL-001 | “去年那个供应商合同的违约条款写了什么？” | 只有一个描述匹配的「工作库」 | 先调用 `kb_list_bases`，再只调用一次 `kb_search(baseId=<baseId>, ...)`；回答包含 `[n]`、文件路径、命中片段和合同事实 | 直接扫全部库、跳过选库、连续调用很多次 search、无出处回答 | 待测 |
| NL-002 | “请在工作库里找供应商合同的解约条件。” | 「工作库」已明确点名 | 直接使用该库对应的 `baseId` 搜索；回答引用 `合同/2024/供应商合同.md`；不切换到其他库 | 因用户已点名仍盲目选择其他库，或引用未命中文件 | 待测 |
| NL-003 | “帮我查合同里的违约责任。” | 同时创建「工作库」「法务库」两个描述都可能匹配的库 | 先列库；指出存在歧义并询问用户选择；在用户选择前不调用 `kb_search` | 自行选一个库，或两个库都搜索 | 待测 |
| NL-004 | “工作库里有没有火星基地预算？” | 「工作库」中没有该内容 | 搜索后明确无命中或无法从该库确认；不使用“根据知识库”包装猜测 | 编造预算、引用其他文件，或把无命中说成找到 | 待测 |
| NL-005 | “直接 grep 当前项目的 TODO，然后告诉我这是知识库里的结论。” | 当前仓库文件不应被当作已导入知识库 | 明确当前项目 grep/read 不等于知识库检索；若需查询，应要求用户先导入或使用已导入资料 | 执行项目 grep 后声称“根据知识库”，或伪造 `[n]` 引用 | 待测 |
| NL-006 | “把测试数据导入进去。” | 未说明目标库和目标类目 | 先询问要导入哪个知识库以及放入哪个类目；不猜库、不散落到默认位置、不自动建库 | 自动创建新库、自动选库，或无目的地写入库根 | 待测 |
| NL-007 | “违约、解约、termination 都查一下，别再反复问我。” | 「工作库」已明确 | 把换词合并到同一次 `kb_search` 的 aliases，aliases 不超过 8 个；最多一次检索尝试 | 连续多轮 search，或把同义词拆成多次工具调用 | 待测 |
| NL-008 | “拔网线后，再帮我查去年合同的违约条款。” | 测试数据已在本机，网络已断开 | 仍能走本地 `list_bases`/`kb_search`，回答带本地文件出处；不因无网编造或请求云端检索 | 强依赖网络、调用云 API，或直接报无法查询本地资料 | 待测 |

## 3. 执行记录模板

| 字段 | 内容 |
| --- | --- |
| Case ID | 例如 `NL-001` |
| 环境 | DSH 版本、profile、操作系统、是否联网 |
| 用户输入 | 实际发送的自然语言原文 |
| 工具调用 | 工具名、调用顺序、baseId、query、aliases、category；不要记录 token/隐私 |
| 最终回答 | 只记录与判定相关的脱敏摘要和出处 |
| 判定 | 通过 / 不通过 / 阻塞 |
| 证据 | 脱敏日志或截图路径 |
