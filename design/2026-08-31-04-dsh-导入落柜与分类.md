# 导入到知识库：人指定目录，AI 只推荐不擅自归类

> 日期：2026-08-31  
> 序号：04（同日 01 是 TB 架构；02 是文件夹 grep MVP；03 是 SQLite FTS）  
> 文件名保留「落柜」为历史标题；正文用语与 02/05/06 统一：**知识库**（原「柜」）、**类目**（原「格子」，即子文件夹）。界面与 Skill 不写开柜、落柜。  
> 本文是 canvas「导入落柜」的原文誊写，已按产品用语改过。

类目就是库下面的相对文件夹。导入必须先选库（哪个知识库），再选类目（哪个相对路径）。缺文件夹就创建；缺知识库不创建。自动归类第一版不做——放错知识库，后面 grep 永远搜不到。

> **和检索漏斗绑在一起**  
> 查询第 0 步是选择知识库、第 1 步是对上类目文件夹名。导入时放错位置，不是「以后还能搜到、只是排后面」，而是那个知识库根本不会被打开。所以导入到哪是产品决策，不能交给模型默默完成。

| | |
|--|--|
| **人指定** | 目标库 + 类目路径是必填项 |
| **可建文件夹** | 类目目录不存在就 mkdir -p |
| **不建新库** | 知识库必须先单独创建 |
| **AI 只推荐** | 建议 1～3 个位置，等人确认 |

---

## 建库时就要写一张给 LLM 看的卡片

知识库不是只有一个文件夹名。创建知识库时，人要留下短描述和别名，供查询第 0 步选库。这不是正文，是库卡片上的标签：选哪个库看标签，不要先把所有文件名倒给模型。

> **渐进式披露：先看库卡片，再看类目，最后才翻页**  
> `kb_list_bases` 只返回各库的卡片（标题、描述、别名、类目名、约多少篇），不含文件名和正文。模型对上描述再选定一个 `baseId`。需要时再看该库文件夹树。最后才 `kb_search` 取十几段。描述空着也能搜，但模型容易选错库。

| 字段 | 创建时 | 给谁看 | 作用 |
|------|--------|--------|------|
| id | 系统生成 | 路径 / 工具参数 | UUID；`bases/<uuid>/`；创建后不改，也不在创建/编辑表单展示 |
| title | 必填 | 人 | 工作库；设置页上的名字；不能与已有知识库重复 |
| description | 必填，可短 | LLM 选库；人也读 | 这个库装什么、什么问题该开它、什么不要放 |
| aliases | 建议 | LLM | 工作、公司、合同库；和问题里的词对上 |
| whenToUse / whenNotToUse | 建议 | LLM | 两个库都像时用来排除；可写进 description |

### 卡片写什么（例：工作库）

标题：工作库。别名：工作、公司、合同库。

描述：公司合同、会议纪要、供应商往来。问条款、纪要、交付开这个库。个人账单、家庭、医疗不要放。

两三句即可。不要把文件清单写进描述——清单会过期，渐进披露的下一层才展开类目和文件名。

### 存在哪

写进 `catalog.json` 的 `bases[]`，和「上次用哪个、大约多少篇」放一起。文件夹 `bases/<uuid>/` 仍然是原文货架。

创建入口：设置页「新建知识库」，或单独命令。导入路径不创建库，因此描述不会在 ingest 时被跳过。

没有聊天模型也能建库：人自己写两句。AI 可以代拟描述，人改完再存。不阻塞「拔网线还能导入」。

## 查询时按层揭开，不要一次倒完

和漏斗第 0 步是同一件事。工具返回越往下越厚；上一层够用就停下。

| 层 | 工具 | 模型看见什么 | 故意不给什么 |
|----|------|--------------|--------------|
| 0 库卡片 | `kb_list_bases` | 每个库：id、标题、描述、别名、类目名列表、约多少篇 | 文件名、正文、其他库的内部结构细节 |
| 1 类目 | 选定 `baseId` 后再列类目 | 该库文件夹树；可选一句类目说明 | 正文、其他库 |
| 2 翻页 | `kb_search` | 该库（可选某类目）里 8～20 段，带路径 | 未命中全文、未选的知识库 |

> **Skill / 硬规则**  
> 用户没点名库时，必须先 `kb_list_bases`，用描述和别名选库，禁止默认扫全部 `bases`。两个库的描述都像，就问人，不要两个都搜。类目文件夹名仍参与第 1 步；描述解决的是「先选哪一个知识库」，不是替代文件夹。

## 一次导入要填什么

设置页、斜杠命令、对话里调 `kb_ingest`，同一套字段。源在本机；目标永远落在 `bases/<库>/` 下面。

| 字段 | 谁填 | MVP | 说明 |
|------|------|-----|------|
| baseId | 人必选 | 要 | 哪个知识库。没有「默认扫全部 bases」 |
| sourcePath | 人选文件或文件夹 | 要 | 本机路径；后缀白名单 md/txt |
| destCategory | 人指定或从推荐里点选 | 要 | 相对路径，如 contracts 或 合同/2024 |
| preserveTree | 可选开关 | 要 | 源是文件夹时，是否保留相对子目录 |
| createMissing | 默认开 | 要 | 只创建 destCategory 这条链，不创建新库 |
| onConflict | 默认 skip | 要 | 指纹相同跳过；同名不同内容则改名 |
| suggestOnly | 对话里可选 | 后做 | 只出推荐、不拷文件 |

## 三种导入方式（第一版只做前两种）

### ① 指定类目（MVP）

人选库，再填或点选类目路径。所有文件平铺进 `bases/<uuid>/contracts/`。

路径不存在：创建中间层。这是主路径，断网也能用。

### ② 保留源树（MVP）

源文件夹里已有 `contracts/`、`meetings/`，导入时挂到某个库根（或某个父类目）下，相对结构原样拷。

`destCategory` 为空 = 挂在库根。仍禁止写出 `bases/<uuid>` 之外。

### ③ AI 推荐（后做）

读文件名、标题、前约 2KB，对照本库已有文件夹，给出 1～3 个位置和一句理由。人点确认才拷。

没有聊天模型、或拔网线：退回 ①②，或进 `_inbox` 等人后分。

## 操作从哪进来

人和 AI 走同一套 `kb_ingest`，只是填表的方式不同。

| 入口 | 人怎么操作 | 目录怎么定 |
|------|------------|------------|
| 设置页「导入」 | 选库 → 选源路径/文件夹 → 类目输入框（可点已有，可打新路径）→ 确认 | 输入框就是 destCategory；点「新建」等于 mkdir -p 后再拷 |
| `/kb ingest` | `/kb ingest ~/notes/供应商.md --base <baseId> --to 合同/2024` | `--to` 缺省则问一句，或用上次这个库用过的类目 |
| 对话里让 AI 导 | 用户说「把这份放进工作库合同类目」；AI 调 `kb_list_bases` 再 `kb_ingest` | 用户话里已经有库名就直接用；没有就先问，禁止猜一个新库 |

## 目录不存在时怎么建

| 对象 | 不存在时 | 为什么 |
|------|----------|--------|
| 类目文件夹 destCategory | 创建整条链（mkdir -p） | 人已经指定类目；创建便宜 |
| 知识库 baseId | 拒绝，提示先「新建知识库」 | 多一个库会污染选库；不能随手长出来 |
| `_inbox` | 库里没有未归类时，仅当人选择「先堆着」才创建 | 不当默认黑洞，避免永远不去归类 |
| 源路径上的目录 | 不创建、不改源 | 导入只读用户指定路径，写入只限插件数据目录 |

### 路径安全（写入前必须过）

`destCategory` 解析后必须仍在 `bases/<baseId>/` 下。拒绝 `..`、绝对路径、符号链接逃出。

允许中文文件夹名（「合同」），因为查询第 1 步是拿问题里的词对文件夹名。

建议深度不超过 4 层；更深不禁止，界面提示「过深会影响选库和浏览」。空段、首尾斜杠去掉。

合法：`合同/2024`、`contracts`、`_inbox`。非法：`../life`、`/etc`、`合同/../../life`。

## AI 推荐怎么做、自动归类为什么不做

### 推荐（可以后做，规则先定）

单独工具 `kb_suggest_placement`：只读、不拷文件。输入源路径 + `baseId`；输出 1～3 条 `{ destCategory, confidence, reason }`。

优先匹配本库已有文件夹名；实在没有才提议新名字，仍等人点「用这个并创建」。

依据：文件名、一级标题、前 2KB。不跑完全文、不调网上嵌入接口。导入时默认不调网上大模型——和 06 一致；当前对话模型在人已经开口时可以建议。

### 自动归类（第一版禁止）

模型把文件默默放进它认为对的知识库，验收过不了：

- 放错知识库 = 漏斗第 0 步永远扫不到。
- 断网 / 没有本地聊天模型时导入会卡住，和「拔网线还能导入」打架。
- 批量 200 篇若每篇调一次模型，又慢又贵，且类目不稳定。

> **以后若做「自动」：也只是对 `_inbox` 的二次整理**  
> 人先用 ① 或 ② 进库（可进 `_inbox`）。事后批处理：对 inbox 里每篇给出推荐，人一次勾选确认。仍然没有「导入当时无确认地改类目」。规则匹配（文件名含「合同」→ `contracts`）可以做，那是字面规则，不是模型擅自决定。

## 走一遍：指定目录 + 不存在则创建

源：`~/Downloads/供应商合同.md`。目标库「工作库」已存在（使用其系统生成的 `<baseId>`）；类目 `合同/2024` 还不存在。

| 步 | 系统做什么 | 结果 |
|----|------------|------|
| 1 选库 | 确认 `bases/<baseId>/` 存在 | 存在则继续；不存在则停，请先建库 |
| 2 解析目标 | `destCategory = 合同/2024`，规范化、检查不出界 | 合法相对路径 |
| 3 建目录 | `mkdir -p bases/<baseId>/合同/2024/` | 新建 合同 和 2024 两层 |
| 4 拷贝 | 拷成 `bases/<baseId>/合同/2024/供应商合同.md`；算指纹 | 原文在文件夹里 |
| 5 登记 | 可选 catalog 记指纹；失败项看得见 | MVP 可以很薄 |
| 6 返回 | 告诉人：进了哪个库、哪条路径、新建了哪些文件夹 | 人能对上设置页树 |

## 第一版明确不做

| 不做 | 若做了会怎样 |
|------|----------------|
| 导入时模型自动选库、自动建库 | 库会乱长；查询无法「先选库」 |
| 导入时默认调网上大模型分类 | 断网不能导入；和知识库离线验收冲突 |
| 没有 destCategory 就按「意思」散落到多个类目 | 同一批文件不知去哪；无法审计 |
| 把源目录监视成自动入库 | 写文件 ≠ 进知识库，见 05 |
| 类目做成标签库、和文件夹脱钩 | MVP 检索靠开文件夹；标签没有物理目录 |
| 查询时跳过库卡片、把全部文件名倒给模型 | 没有渐进披露；选库失败还浪费上下文 |

对照：31-02 文件夹即类目与 `catalog.json`；01 §4.2 路径导入；05 写文件不会自动进库；06 导入时不默认调网上大模型抽关系。本页补「建库卡片 + 导入到指定知识库与类目」。
