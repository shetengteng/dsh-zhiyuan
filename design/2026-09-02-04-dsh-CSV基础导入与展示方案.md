> 结构修订：2026-09-03 — M0 已接入 `src/content/host-api.ts`；格式白名单、导入、预览、搜索和编辑能力不再分散在 `identity.ts`、`bases.ts`、`ingest.ts` 与 Client 条件分支中。

## 1. 改造前现状

改造前代码**不支持 CSV 导入或展示**；本节保留基线，便于逐项对照实现结果：

| 链路 | 现状 | 结论 |
|------|------|------|
| 导入 | `src/identity.ts` 的 `TEXT_EXTS` 只有 `.md` / `.txt` / `.markdown`；`ingestOne` 因此拒绝 `.csv` | 不支持 |
| 系统选文件 | Windows 筛选器仅列 Markdown/Text | 不支持 |
| 库树、篇数、去重 | `bases.ts` 与 `ingest.ts` 都按 `TEXT_EXTS` 扫描 | CSV 即使手工放进库也不可见、不计数、不参与去重 |
| 搜索 | `search.ts` 的 ripgrep glob 未含 `*.csv` | 不支持 |
| 预览 | `readEntry` 能按 UTF-8 读任意库内路径，但界面会交给 `MdEditor`；树中打开的内容可编辑 | 不能可靠展示 CSV，且不应让 Markdown 编辑器改写 CSV |

本档先补一条能交付的基础路径：**只导入 UTF-8 CSV（允许 BOM），保留原始 CSV 字节，只读等宽文本展示，并加入现有全文搜索。**

## 2. 范围

### 本期做

- 导入单个 `.csv` 或含 `.csv` 的目录，沿用现有同指纹跳过、同名改名、配额和保留目录语义。
- CSV 出现在库树、篇数、哈希扫描和 `kb_search` 中。
- 设置页预览弹框、对话右侧命中预览都以**只读纯文本**展示 CSV。
- 允许 UTF-8（有无 BOM）；拒绝非法 UTF-8、NUL 和除 tab / CR / LF 外的控制字符，保证 ripgrep 与 `readFile(..., 'utf8')` 的行为一致。
- 在 Host 强制 CSV 只读；界面层不是唯一保护。

### 本期不做

- GBK / GB18030 / UTF-16 转码、换行归一或重新写出 BOM。
- `.xlsx`、`.xls`、`.xlsm` 导入。
- RFC 4180 表格解析、表头补全、列名化 excerpt、单元格视图、排序、筛选或公式计算。
- 修改 CSV 内容、导出、另存或将 CSV 渲染为 Markdown 表格。

因此，Windows Excel 导出的 GBK CSV 在 M0 会明确失败；不要“先放行、显示乱码”。编码归一与 XLSX 多输出由 03 档的 Converter 阶段完成。

这里的“CSV”特指带分隔符的文本文件，不承诺接受任意编码或任意方言。M0 的可用范围是严格 UTF-8（可带 BOM）；分号/Tab 方言虽然可以原样检索和展示，但不会在 M0 被改写成统一逗号 CSV。需要“常见 CSV 输入后转换成知源规范 CSV”时，按 03 档 M1 先固定编码、方言解析和规范输出，再实现 Converter。

## 3. M0 的数据流

```text
用户选择 / 拖入 .csv
  → Host 扩展名白名单 + 文件大小检查
  → 读取至多 min(maxFileBytes, 20 MiB) 的 Buffer，TextDecoder('utf-8', { fatal: true })
  → 严格 UTF-8 + 控制字符 + 物理行校验；通过后用同一 Buffer 原子写入
  → bases/<id>/<category>/<name>.csv
  → 树 / 计数 / hash / rg 搜索
  → CSV 预览组件（React 文本节点，不经 Markdown 解析）
```

M0 不改变合法 CSV 的字节、分隔符、引号或换行；UTF-8 BOM 也原样保留。预览和搜索读取时去掉展示用 BOM，避免首列出现 `\uFEFF`，但不回写文件。

### 3.1 大小边界

| 边界 | 默认/固定值 | 说明 |
|------|--------------|------|
| 单文件导入 | 偏好 `maxFileBytes`，默认 **5 MiB** | 可在偏好中调整；CSV 另有 20 MiB 硬上限，因此 CSV 有效上限为 `min(maxFileBytes, 20 MiB)` |
| CSV 读取/搜索 | **20 MiB** | 超过则不导入，避免“能导入但无法搜索/预览” |
| CSV 展示文本 | **200,000 个 JS 字符** | 只影响预览窗口，不改变库内原始字节 |
| 单条物理行 | **64 KiB** | 不含 CR/LF；超出返回 `csv_line_too_long` |
| 单库文字总量 | 偏好 `maxBaseBytes`，默认 **10 GiB** | 每个成功写出的文件按实际写出字节累计 |

这里的 20 MiB 是 M0 的安全硬上限，不随 UI 中的单文件偏好无限放大；M1 转换器还要对源体积和规范化输出体积分别复验。

## 4. Host 侧设计

### 4.1 后缀与搜索白名单

由 `src/content/host-api.ts` 的 `contentRegistry` 定义唯一来源。它区分“用户可导入的源格式”和“库内可搜索、可预览的条目格式”：

```ts
SourceFormat: markdown | plain-text | csv | xlsx
EntryFormat: markdown | csv

contentRegistry.sourceExtensions() // M0: .md / .markdown / .txt / .csv
contentRegistry.entryExtensions()  // M0: .md / .txt / .markdown / .csv
contentRegistry.searchGlobs()      // 从 entryExtensions 派生
```

后缀统一转小写，因此 `.CSV` 也接受。`search.ts` 直接使用 `contentRegistry.searchGlobs()`；库树、篇数与哈希扫描使用 `contentRegistry.isStoredEntryPath()`。未来 `.xlsx` 只会是 `SourceFormat`，转换后产生一个或多个 `EntryFormat.Csv`，不会被误当成库内正文。

### 4.2 严格 UTF-8 预检

在 `src/content/csv/server/encoding.ts` 放无副作用的纯函数和受限读取，不引入第三方依赖。它属于 CSV 文件类型模块；M0 尚不启用 Converter，M1 的 CSV Worker 直接复用：

```ts
type ValidatedCsv = { bytes: Buffer; text: string; byteLength: number }
type CsvValidation =
  | { ok: true; value: ValidatedCsv }
  | { ok: false; code: 'csv_encoding_invalid' | 'csv_control_character' | 'csv_line_too_long' | 'file_too_large'; message: string }

export async function readValidatedUtf8Csv(sourcePath: string, maxBytes: number): Promise<CsvValidation>
export function isCsvPath(path: string): boolean
export function stripUtf8Bom(text: string): string
```

`ingestOne` 在常规文件、后缀和 `maxFileBytes` 校验之后调用 `readValidatedUtf8Csv`：

1. 通过文件句柄分块读取，最多取 `min(maxFileBytes, 20 MiB) + 1` 字节；文件在读取期间变大也不能无界分配。
2. 用 Node 内置 `TextDecoder('utf-8', { fatal: true })` 解码；不使用替换字符掩盖坏字节。
3. 解码文本含 NUL 或除 tab / CR / LF 外的控制字符即失败。分隔符、引号、空行和多行字段在 M0 原样保留。这样 M0 不会把 M1 会拒绝的 `\x01` 遗留在库内。
4. 单条物理行内容（不含 CR/LF）不超过 `CSV_MAX_PHYSICAL_LINE_BYTES`（64 KiB）；M0 不解析 RFC 4180 逻辑记录。
5. 返回 `{ bytes, text, byteLength }`。哈希与写入必须使用同一份 `bytes`，写入采用库内临时文件 + `rename`，失败清理临时文件；不再校验一次、再 `copyFile` 一次。
6. 校验失败**返回**稳定 code 和通用文案，例如 `csv_encoding_invalid` / `csv_control_character`；不把解码器原始异常、文件内容或绝对路径回传给 UI / 工具结果。

普通 md / txt / markdown 保持现有复制语义。本期不把 `.csv` 放进 Converter registry；M1 才将这条“验证 + copy”路径替换成 03 档的 CSV 转码 Converter，预览接口不再变化。

**批次失败语义必须先于校验实现。** 当前 `ingest()` 直接 `await ingestOne()`，任意 throw 都会中断目录中的后续文件。实现时每个已枚举文件都必须收口为一条 `IngestFileResult`：预期校验失败通过 `CsvValidation` 返回；I/O、哈希、copy 和写后记账的意外异常也在单文件边界转换成 `failed` + 通用 `io_failed`。外层循环继续处理下一个文件。成功结果携带写出字节数，外层用该值累加配额，不能在循环外再 `stat()` 而产生逃逸异常。

```ts
type IngestFileResult = {
  // 兼容现有工具输出；成功时等于 destinationPath，失败时为源文件相对名
  relPath: string
  sourceRelPath: string
  destinationPath?: string
  status: 'copied' | 'skipped' | 'renamed' | 'failed'
  code?: 'ext_denied' | 'file_too_large' | 'quota' | 'path_escape' | 'csv_encoding_invalid' | 'csv_control_character' | 'csv_line_too_long' | 'io_failed'
  reason?: string // 仅稳定、通用文案
  writtenBytes?: number
}
```

`writeEntry` 抛出的 `read_only_format` 则是 API 级错误，加入 `KbErrorCode`；它不同于导入单项失败，不能只塞进 `reason`。

### 4.3 三条预览读取路径（不得共用“从文件头截断”）

`CSV_PREVIEW_MAX_CHARS = 200_000` 是 CSV 展示文本上限，`CSV_PREVIEW_MAX_BYTES = 20 MiB` 是 Host 预览读取上限；两者都不能决定搜索命中的展示位置。Markdown / txt 保持现有全文读取与编辑语义；只为 CSV 增加下列窗口策略和 payload 字段。Host 只接受封闭的 view 模式，客户端不能传范围或大小：

```ts
type EntryFormat = 'markdown' | 'csv'
type EntryPreviewView = 'tree' | 'search-hit'
type PreviewStatus = 'ready' | 'stale' | 'fallback'

type ReadEntryResult = {
  path: string
  text: string
  format: EntryFormat
  view: EntryPreviewView
  windowStartLine: number
  windowEndLine: number
  focusLine?: number
  focusColumnByte?: number
  truncation: 'none' | 'before' | 'after' | 'both'
  totalChars: number
  previewStatus: PreviewStatus
  capabilities: { canEdit: boolean }
}
```

| 入口 | 命令参数 | 返回窗口 |
|------|----------|----------|
| 库树打开文件 | `view: 'tree'` | 固定上限的文件头窗口，`windowStartLine=1`；若截断，标 `after`。用户未选择命中行，展示开头是预期行为 |
| 设置页搜索打开命中 | `view: 'search-hit'` + 已验证的 `matchLine` / `matchColumnByte` | 固定上限内、围绕命中的窗口；无论命中在文件前后都必须包含命中；返回真实的起止行与截断方向 |
| 对话 `kb_search` 引用卡打开右栏 | 与设置页完全相同的 `search-hit` 请求和响应 | 复用同一窗口策略，不能退化成文件头 |

- `readEntry` 只读取 `contentRegistry.entryExtensions()` 内的文件，并保持现有路径归一、库根 containment 与 symlink 检查；CSV 的窗口与命中元数据放在 `src/content/csv/` 和 `src/content/shared/`。`commands.ts` 仅转发 `EntryPreviewView` 和正整数命中位置，拒绝自定义字节数、行半径或路径外参数；缺少 `view` 时保留树视图默认值以兼容旧调用。
- CSV 的 UTF-8 解码也走严格路径；发现库内文件被手工替换为坏字节或控制字符时，以通用错误失败，而不是向前端发送替换字符。
- `search.ts` 调 ripgrep 时使用 JSON 输出并加入 `--column`，把命中所在物理行内的一基 UTF-8 字节列作为 `SearchHit.matchColumnByte` 带回，同时返回该文件的 `sourceFingerprint`。Host 以自身重新读取的 Buffer 和行号校验该位置；指纹或位置不一致时返回 `previewStatus: 'stale'`，不伪造高亮，Client 退回 search 已返回的 excerpt。用含中文的 fixture 固化这一字节列契约。
- 极长物理行是窗口实现的边界：M0 在导入时限制 `CSV_MAX_PHYSICAL_LINE_BYTES`（建议 64 KiB），使固定窗口可以完整保留命中行；超限返回 `csv_line_too_long`。RFC 4180 逻辑记录和跨行字段仍属于 M1，不在 M0 切列。
- `writeEntry` 遇到 `.csv` 返回 `read_only_format`；树中仍允许走既有确认流程删除。

这一调整不改变 Markdown 编辑功能。`PreviewDialog` 的 `editable` 与 `deletable` 必须拆开：库树打开 CSV 为 `editable=false, deletable=true`；搜索命中仍为 `false, false`。

`writeEntry` 在所有可编辑文本写入前都必须执行 `assertNoSymlinkEscape`，防止已有链接将写操作导出库根；这是 M0 的安全验收项，适用于所有可编辑文本，不只是 CSV。

### 4.4 搜索

M0 只提供原始全文检索：

- ripgrep 使用 `contentRegistry.searchGlobs()`、`--glob-case-insensitive`、`--column` 和结构化 JSON 输出；`SearchHit` 增加 `matchColumnByte` / `sourceFingerprint`，其余行号与上下文语义不变。
- CSV 已经 UTF-8 且不含 NUL，所以不会因二进制分类被跳过。
- excerpt 保持物理行上下文；不假装能按 CSV 记录或列定位。合法带引号换行的复杂 CSV 可能跨多行，这是 M1 的 RFC 4180 解析范围。
- 搜索命中预览须分派到 CSV 纯文本组件，不能复用 Markdown 解析器。

## 5. Client 展示设计

`src/content/csv/client/CsvPreview.tsx` 供设置弹框和右侧详情栏共用；`src/content/client-api.tsx` 是 Client 唯一的格式分派点。

| 要求 | 决定 |
|------|------|
| 渲染 | 使用 React 文本节点放进 `<pre>`；绝不使用 `dangerouslySetInnerHTML`、HTML 字符串拼接或 CSV 公式求值 |
| 版式 | 等宽字体、保留空白、横向滚动；不把逗号或分号强行拆成 HTML 表格 |
| BOM | 调用 `stripUtf8Bom` 后显示 |
| 命中 | 按 Host 回传的 `windowStartLine` / `focusLine` 给行添加 React `<mark>` / class；字段内容仍作为文本，不生成链接 |
| 大文件 | 顶部明确“显示文件开头”或“显示命中附近”；`truncation` 为 `before` / `after` / `both` 时显示对应提示。不得以文件头冒充命中窗口，也不提供绕过上限的前端按钮 |
| 可编辑性 | 永远只读，无 Markdown 工具栏、保存按钮或单元格交互 |

`PreviewDialog` 和 `KbPreviewPanel` 都调用 `EntryPreviewContent`，它只按 Host 返回的 `EntryFormat` 选择 Markdown 或 CSV 组件，Client 不从路径推断格式。编辑能力来自 Host 返回的 `capabilities.canEdit`，但 Host 写入时仍再次校验。CSV 不经过 Tiptap，因此 `=HYPERLINK(...)`、`javascript:`、`# 标题` 都只是文本。

对话右栏的加载链固定为：点击命中卡 → Client 以 `baseId + path + matchLine + matchColumnByte + sourceFingerprint` 调 Host `read(view: 'search-hit')` → Host 返回窗口或明确错误 → Client 只在当前请求仍有效时替换预览。必须有 idle / loading / ready / error / stale 状态；断连、旧请求和 Host 错误不能把旧文件正文写回当前命中。无 preview payload 时只能显示命中卡自带的 excerpt，不能让 `kb_search` 携带每个命中文档全文。

设置页变更：

- `PrefsPage.tsx` 在“解析器”中显示已启用的“CSV（UTF-8，只读）”。
- `AdditionalDialogs.tsx` 导入帮助更新为“支持 md / txt / markdown / UTF-8 csv”。
- `pick-source.ts` 的 Windows `OpenFileDialog.Filter` 第一组改为 `Markdown/Text/CSV|*.md;*.txt;*.markdown;*.csv`；不能把 CSV 放进默认看不见的独立组。macOS / Linux 可继续选择全部文件，Host 白名单仍为最终判定。
- `tools.ts` 的 `kb_ingest` 描述更新为“支持 UTF-8 CSV；CSV 只读”，不承诺 Excel 或自动转码。

## 8. 后续衔接

M0 的目标是尽快让已是 UTF-8 的 CSV 可用；它不是 03 档的替代品。

M1 接入 `convert/registry.ts` 后，`.csv` 优先进入 CSV Converter：支持受控 GB18030 / UTF-16 解码、写为 UTF-8+BOM，并将 XLSX 各 sheet 转为多个 CSV。届时复用本档的 `CsvPreview`、`EntryFormat`、搜索白名单、只读策略和 `src/convert/csv/encoding.ts`；仅把校验调用边界从 Host copy 路径迁到 CSV Worker。再下一步才做 RFC 4180 记录级 excerpt，不应在 M0 用不完整的 `split(',')` 冒充解析。

## 9. 安全审查卡

| 项目 | M0 约束 |
|------|------|
| 信任边界 | 文件路径与 CSV 内容均不可信；Host 是唯一白名单、大小、编码和路径检查点 |
| 输入 | 后缀大小写归一、常规文件、既有大小/配额、严格 UTF-8、仅允许 tab / CR / LF 控制字符、物理行上限 |
| 文件与 IPC | `resolveDest` + containment + symlink 检查；CSV 使用同一份已校验 Buffer 原子写入；tree / search-hit 固定窗口；客户端不能要求任意字节数、行半径或范围 |
| 输出与渲染 | 原字节 copy，不执行公式；React 文本节点渲染，不注入 HTML、链接或脚本 |
| 错误与日志 | 对用户给稳定通用错误；不记录 CSV 正文、绝对路径或解码器原始异常 |
| 依赖 | 不新增依赖；仅 Node 内置解码器与已有 ripgrep |
| 待测 | 单元、回归、坏编码 / 控制字符、安全渲染、symlink、文件末段命中与手工大文件预览 |
