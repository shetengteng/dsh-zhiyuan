# DSH Agent 创建与使用

本文记录 DSH（DeepSeek Harness）里 Agent 的实际入口：`AGENTS.md`、Agent Preset、子 Agent 分别干什么，以及如何用自然语言创建、如何在 Web UI 里开会话。路径以本机 `$DSH_HOME` 默认值 `~/.dsh`、Profile `web` 为准。

DSH **没有**「设置 → 新建 Agent」表单。一个可切换的 Agent 就是一份 **Preset 目录**。

---

## 1. 先分清三件事

| 机制 | 干什么 | 本机位置 |
|---|---|---|
| **`AGENTS.md`** | 喂给**当前会话**的工作区规则，不会在选择器里多出一个 Agent | 全局 `~/.dsh/AGENTS.md`；项目则写在仓库根 |
| **Agent Preset** | 一个会话的人设 + 工具集。选择器里看到的「标准模式 / 创造模式」就是它 | 内置：安装目录；自定义：`~/.dsh/.agent-presets/<id>/` |
| **子 Agent** | 同一会话里主 Agent 派出去的工人 | 标准预设已挂 `subagent` 工具，用自然语言派工即可 |

`AGENTS.md` 只是说明；Preset 才是「开哪种 Agent」；子 Agent 是「这一句任务里并行干活」。

---

## 2. `AGENTS.md`：工作区说明

由 `@deepseek-ai/dsh-agent-instructions` 加载（`dsh-base` 默认带上，预算 65536 字节）。首次请求打进历史，更具体的文件优先。

加载顺序（宽 → 窄）：

1. 全局：`~/.dsh/AGENTS.md`
2. 从项目根（遇到 `.git` 停止）走到会话工作目录，每个目录里：
   - 基础：`AGENTS.md`，然后 `CLAUDE.md`
   - 本地覆盖：`AGENTS.local.md`，然后 `CLAUDE.local.md`

同一目录内容去空白后相同的文件只渲染一份。子目录里的文件不会开场全扫，要等 `read` / `write` / `edit` 碰到那个目录才会追加。

直接写文件即可，不必再配插件。需要改预算或候选文件名时，先 `dsh --profile web --dump-config` 看 `agent-instructions` 的真实 row id，再改 `~/.dsh/profiles/web/cordis.patch.yml`。

`~/.dsh/profiles/web/cordis.patch.yml` 是给**整个 dsh 进程**加插件用的（例如知源），不是建 Agent 的地方。本机该文件目前是空数组 `[]`。

## 3. 内置 Preset：现在就能开

本机 `~/.dsh/settings.yaml`：

```yaml
agent-presets:
  default: standard
```

内置目录（**不要改**，升级会覆盖）：

```text
~/.dsh/profiles/node_modules/@deepseek-ai/dsh/config/agent-presets/
```

| 选择器显示名 | id | 用途 |
|---|---|---|
| 标准模式 | `standard` | 日常写代码。文件、Shell、检索、Skills、计划、子代理 |
| 代码模式 | `code` | 偏批量编码 |
| 极简模式 | `minimal` | 几乎只有 shell + 编辑器 |
| 创造模式 | `cordis` | 用自然语言帮你**创建自定义 Preset**，权限高，不要当日常模式 |

### 在 Web UI 里开会话

1. 打开 DSH Web（一般是 `http://127.0.0.1:3080`）
2. 左侧点 **新建会话**
3. 在工作区旁边的 **Preset 下拉框**里选模式
4. 工作区选对应仓库（改知源就选 `dsh-zhiyuan`）
5. 发第一条消息

标题旁会显示当前模式。发过第一条后，这个会话的 Preset **不能再改**；要换模式就再新建一个会话。改 `settings.yaml` 的 `default` 只影响之后新建的会话。

日常改知源插件：直接开 **标准模式** 即可。仓库根 `AGENTS.md` 会自动进上下文。

## 4. 自定义 Preset：做出「知源助手」这类选项

自定义预设一个目录一份：

```text
~/.dsh/.agent-presets/<preset-id>/
  ├── preset.yml          # 选择器里的显示名
  └── agent.cordis.yml    # 人设 + 工具行
```

`<preset-id>` 只能是 `[a-z0-9][a-z0-9-]*`，例如 `zhiyuan-dev`、`reviewer`。

截至本文撰写时，本机 **还没有** `~/.dsh/.agent-presets/`，所以选择器里没有「知源助手」。那是自定义显示名，要先建出来才会出现。

### 推荐：用创造模式、自然语言创建

1. 新建会话 → Preset 选 **创造模式**
2. 把下面整段发给它（它会加载 `editing-cordis-compositions` skill，调用 `agentPresets.copy()`）
3. 它要写 `~/.dsh/.agent-presets/` 时会弹沙箱授权，点允许
4. **再新建一个会话**，在 Preset 下拉框里选刚建的显示名
5. 工作区选对应仓库后再开始干活

创造模式那场只负责「造出这个选项」，真正写代码必须换一场新会话。

可直接粘贴：

```text
请加载 editing-cordis-compositions skill。

从 standard 复制出 3 个用户预设，不要改任何内置预设：

1. id: reviewer
   显示名：审查员
   人设：只做代码审查。只找正确性、安全和回归。不要改文件，不要跑会改状态的命令。
   禁掉 tool-bash。

2. id: explorer
   显示名：探查员
   人设：只读探查仓库结构、调用链和关键文件，给出路径清单。不要改文件。

3. id: zhiyuan-dev
   显示名：知源助手
   人设：你在维护 dsh-zhiyuan 知识库插件。改 src/ 前先确认范围；源码注释用中文；不要手改 lib/。

每个都要写 preset.yml 的 name 和 description。复制用 agentPresets.copy()。
改完后对每个 id 做 standingKeyFor 校验，告诉我哪些已可在新会话里选用。
```

只建「知源助手」时，把上面缩成一条 `zhiyuan-dev` 即可。

文件一落地，选择器里就会出现，一般不用重启。已经开着的会话不会变。

### 备选：自己复制

```sh
mkdir -p ~/.dsh/.agent-presets/zhiyuan-dev
cp -R ~/.dsh/profiles/node_modules/@deepseek-ai/dsh/config/agent-presets/standard/. \
      ~/.dsh/.agent-presets/zhiyuan-dev/
```

然后改两处。

`preset.yml`：

```yaml
name: 知源助手
description: 维护 dsh-zhiyuan 知识库插件的编码 Agent。
```

`agent.cordis.yml` 开头的 persona（会盖掉部署级人设，只作用于这个会话）：

```yaml
- id: persona
  name: '@deepseek-ai/dsh-persona'
  config:
    text: >-
      你在维护 dsh-zhiyuan 知识库插件，模型是 {{model}}，工作目录是 {{cwd}}。
      改 src/ 前先确认范围；源码注释用中文；不要手改 lib/。
```

同文件里若要禁掉 shell：

```yaml
- id: tool-bash
  name: '@deepseek-ai/dsh-tool-bash'
  disabled: true
```

不要从零写 `agent.cordis.yml`。官方要求先 `copy(from, id, name)`，再改副本；漏掉 isolate realm 的服务行会在第二场会话挂载时碰撞。校验用 `standingKeyFor(id)`，不要只看 `list()` 的 `broken` 字段。

## 5. 一个会话里多个工人：子 Agent

标准预设已经挂了 `subagent` / `subagent_fork`。不必先建自定义 Preset，直接在标准模式里下任务：

```text
并行做两件事：
1. 派一个子 Agent 只读探查这个仓库的 CSV 导入链路，列出关键文件。
2. 派另一个子 Agent 审查 src/content/csv，只找正确性和回归风险，不要改文件。
都完成后你来汇总。
```

要点：

- `spawn` 子会话**看不到父对话**，派任务时要把上下文写进 prompt
- `backgroundMode: continuable` 时，父 Agent 可用 `send_message` / `list_agents` / `interrupt_agent`；子 Agent 用 `report` 交回结论
- 进程内子 Agent 才支持 `persona`、`toolFilter`、`maxDepth`；Codex / Claude Code 等外部产品一般不支持，要靠不同 provider 实例 + 不同 `toolName`

同一进程可以并排开多个会话（例如一场「知源助手」写代码、一场「审查员」审）。那是多个 Preset 会话，不是同一聊天里的子 Agent。

若要让主 Agent **工具栏里就有**「审查 / 探查」两个委派按钮，需要在复制出的 Preset 里多次挂 `dsh-tool-subagent`，每个实例 `toolName` 必须唯一。这比创造模式复制三个独立 Preset 更重，日常不必先做。

## 6. 怎么选

| 你想要 | 怎么做 |
|---|---|
| 日常改知源代码 | 新建会话 → **标准模式** → 工作区选仓库 |
| 这一句任务里并行多个工人 | 标准模式 + 自然语言派子 Agent |
| 选择器里固定几个角色，切换着用 | 创造模式 + 第 4 节那段话 → 再新开会话选显示名 |
| 所有会话都遵守同一套项目规矩 | 写仓库 `AGENTS.md` 或 `~/.dsh/AGENTS.md` |
| 默认用哪个 Preset | `~/.dsh/settings.yaml` 的 `agent-presets.default` |
| 给整个 dsh 加插件 | `~/.dsh/profiles/web/cordis.patch.yml` |

没有「设置页勾几个 Agent 然后自动组队」的开关。自然语言能做的是：标准模式当场派工，或创造模式把角色做成可切换的 Preset。
