# 知源：按文件类型组织内容处理（方案 A）

> 日期：2026-09-03
> 状态：已确认，实施中。M0 功能与安全限制保持不变。

## 要解决什么问题

现在 Markdown 和 CSV 的逻辑散在导入、读取、搜索、预览和前端组件中。每新增一种格式，都要在多处增加 `if (.csv)` 或 `if (format === 'csv')`。

这样容易发生不一致，例如导入支持了 CSV，但预览或搜索忘记支持；之前 Markdown 预览丢失也是接口变化后多处逻辑没有同时对齐的风险。

目标是：**同一种格式的导入、搜索、预览和编辑规则放在一起；外层只通过统一接口路由。**

顶层名称使用 `content`，而不是 `formats`。它描述的是从导入到检索、预览和编辑的完整内容生命周期，而不只是扩展名判断。

## 先分清两种格式

| 名称 | 用途 | 例子 |
| --- | --- | --- |
| `SourceFormat` | 用户导入的源文件格式 | md、txt、csv、xlsx |
| `EntryFormat` | 实际写入知识库、可搜索和预览的条目格式 | markdown、csv |

`xlsx` 以后可以导入，但不会直接放进知识库；它会转换成一个或多个 `csv` 条目。

## 统一流程

```text
用户文件
  → 按 SourceFormat 找导入处理器
  → 产生一个或多个 EntryFormat 条目
  → 通用的去重、配额、原子写入

库内文件
  → 按 EntryFormat 找条目处理器
  → 读取预览 / 搜索文本 / 判断是否可编辑
  → Client 按 EntryFormat 选择预览组件
```

格式值使用可序列化的字符串枚举，避免数字枚举在 Host / Client 通讯时含义不清：

```ts
export const EntryFormat = {
  Markdown: 'markdown',
  Csv: 'csv',
} as const
```

## 建议目录

```text
src/content/
  api.ts                      # Host / Client 共用、无副作用的枚举与 DTO
  host-api.ts                 # Host 的唯一内容处理入口
  client-api.tsx              # Client 的唯一内容预览入口
  host-registry.ts            # 按文件后缀路由到类型模块
  host-contract.ts            # registry 与类型模块之间的内部约定
  shared/
    line-window.ts            # 行号、窗口等通用纯函数
    ingest-output.ts          # 原子写入、去重、配额、回滚
  markdown/
    index.ts                  # Markdown / TXT 的唯一注册入口
    server/
      import.ts
      preview.ts
      search.ts
      write.ts
    client/
      MarkdownEditor.tsx
      MarkdownPreview.tsx
  csv/
    index.ts                  # CSV 的唯一注册入口
    server/
      encoding.ts
      import.ts
      preview.ts
      search.ts
    client/
      CsvPreview.tsx
```

Host 和 Client 的入口必须分开：Client 只负责展示，不能读取本地文件、做转码或决定文件权限。

## 外层统一调用

`ingest.ts`、`bases.ts`、`search.ts` 不再自己判断 CSV 或 Markdown，而是通过 `src/content/host-api.ts` 调用：

```ts
contentRegistry.prepareImport(context)
contentRegistry.readPreview(context)
contentRegistry.readForSearch(context)
contentRegistry.writeEntry(context)
contentRegistry.searchGlobs()
```

其中：

- `ingest.ts` 只做遍历目录、批次统计和调用通用写入。
- `bases.ts` 只做库管理、路径 containment 和符号链接检查。
- `search.ts` 只做 ripgrep、合并命中和排序。
- Markdown / CSV 各自决定如何导入、如何预览、如何搜索、能否编辑。它们只向内部 registry 暴露一个类型注册对象，例如 `markdownContentFormat`、`csvContentFormat`。

内容模块外的代码只能依赖三层公开接口：

```ts
// src/content/api.ts
SourceFormat
EntryFormat
EntryPreviewOptions
EntryCapabilities

// src/content/host-api.ts（仅 Host）
contentRegistry

// src/content/client-api.tsx（仅 Client）
<EntryPreviewContent preview={preview} mode="read" />
```

## 前端规则

设置页弹框和对话右侧预览共用 `src/content/client-api.tsx` 的 `EntryPreviewContent` 组件：

```text
preview.format = markdown → MarkdownPreview
preview.format = csv      → CsvPreview
```

是否可编辑由 Host 返回的 `capabilities.canEdit` 决定。前端只负责隐藏保存按钮；Host 写入时仍必须再次校验，不能信任前端。

跨格式 UI 不放进 Markdown 或 CSV 目录：

```text
src/client/settings/preview/
  PreviewDialog.tsx
  preview-request.ts

src/client/toolview/preview/
  KbPreviewPanel.tsx
  preview-state.ts
  preview-width.ts
```

## 和当前 M0 / 后续 M1 的关系

- 当前：只接受 UTF-8 CSV（可带 BOM），导入时保留原字节；表格预览 / 编辑的当前边界见 [CSV 表格预览与编辑](./2026-09-03-03-dsh-CSV表格预览与编辑.md)。
- M1：CSV 导入处理器可以升级为“输入编码 / 方言转换为规范 UTF-8 CSV”。
- M1：新增 `content/xlsx/` 导入处理器，输出多个 CSV；CSV 的搜索和预览逻辑无需重写。

因此，格式路由重构不会提前承诺“任何 CSV 都能导入”，它只是为后续转换留出正确位置。

## 推荐实施顺序

1. 将 `formats` 迁为 `content`，按文件类型整理 server/client，并保持行为不变。
2. 收紧为 `api.ts`、`host-api.ts`、`client-api.tsx` 三个公开边界。
3. 将 PreviewDialog 与会话预览各自移动到对应的 preview UI 域，并保留旧 Markdown preview payload 的兼容处理。
4. 最后再实现 CSV 转码和 XLSX 导入。

## 验收标准

- Markdown 的树预览、搜索命中预览和编辑不回归。
- CSV 的 UTF-8 校验、大小限制、表格预览、编辑和搜索不回归。
- 新增格式时，只新增对应类型目录和 registry 注册，不修改多处业务判断。
- Host 仍负责路径安全、文件格式校验和写入权限。
