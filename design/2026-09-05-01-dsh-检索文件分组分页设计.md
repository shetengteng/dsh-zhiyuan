# kb_search 检索文件分组分页与两档命中设计

> 日期：2026-09-05
> 序号：01（当日首篇）
> 对照：`2026-08-31-02`（文件夹 grep MVP）、`2026-09-01-02`（MVP 技术设计）、`2026-09-03-02`（会话命中预览不写入对话）。
> 决策记录：已与维护者确认三项——分页单元=文件组分页；页体积=字符预算制；命中文本=两档制（列表档 + path 明细档）。预览链路（右侧 details 分区）保持零改动。
> 对外用语：知识库 / 类目 / 命中。

---

## 1. 背景：现状与问题

现状链路（`src/search.ts`）：

```
kb_search → searchBase → 重跑 ripgrep（--json）
  → parseRg 解析全部 match（path/line/column）
  → 对每个命中文件 readForSearch（CSV 全量解析）
  → mergeAdjacent 相邻合并 → diversify 文件轮转打散
  → 全局 offset 切片 topK 条 → 返回 hits + nextCursor(v1: offset)
```

暴露的五个问题：

| # | 问题 | 根源 |
|---|------|------|
| 1 | 分页给 AI 时上下文爆炸 | 每条命中固定带 8 行半径上下文（`SEARCH_CONTEXT=8`），CSV 还要「表头 + 前后 8 条记录」；一页 10 条轻松数千字符 |
| 2 | 一页内记录跨文件交错 | `diversify` 按文件轮转挑选（A1,B1,C1,A2…），AI 上下文碎片化，无法建立单文件命中全貌 |
| 3 | 单文件命中被拆散多页 | 同上；且游标是全局 offset，AI 不知道「该文件还剩多少」 |
| 4 | AI 缺全貌 | 只返回 `hasMore`，AI 只能盲目翻页或过早放弃；不知道共多少文件、多少条、分布在哪 |
| 5 | 翻页成本高 | 每页重跑 rg 且对**全部**命中文件 `readForSearch`（含 CSV 全量解析），只为切出一小页 |

顺带的体积问题：CSV 命中每条 excerpt 都重复一遍表头「列: …」，一页 10 条命中表头重复 10 次。

---

## 2. 目标与非目标

### 目标

1. 分页单元从「全局交错流」改为「文件组」：一页只含完整文件组，预算不够则组内截断、下页续读。
2. 页体积按渲染字符预算控制（MD 单行与 CSV 宽记录体积差一个数量级，按字符比按条数稳）。
3. 命中文本两档制：默认列表档高密度；`path` 入参锁定单文件给 8 行明细档。
4. 首页/每页带命中概览（totalFiles / totalHits / 未展示文件清单），AI 能决策「翻页 / 换词 / path 直跳」。
5. 翻页只读本页涉及的文件，跳过的文件只留计数。
6. Client 命中卡按文件组渲染；预览链路（read RPC 独立按需读盘）零改动。

### 非目标

- 不做持久化索引或缓存（仍是每页重跑 rg 的无状态游标模型）。
- 不改 `SearchHit` 字段（预览契约 `path / matchLine / matchColumnByte / sourceFingerprint` 全保留）。
- 不做「点击组头打开整个文件」的新交互（需要新 read view，扩大契约面，第一版不做；组头纯展示）。
- 不引入向量/语义检索。

## 3. 总体模型：文件组两级分页

```
旧（全局交错流）                新（文件组分页 + 字符预算）
第 1 页: A1 B1 C1 A2 B2         第 1 页: ┌ a.md        3/3 条 ┐ A1 A2 A3
第 2 页: C2 A3 B3 C3 …                   ├ b.csv  2/5 条·截断 ┐ B1 B2
                                         尾注: 共 3 文件 · 12 命中 ·
                                               未展示 c.md(12) d.md(5)
                                 第 2 页: ┌ b.csv 续 3/5 条   ┐ B3 B4 B5
                                         └ c.md        2/2 条 ┘ C1 C2

游标 v1: { offset: 7 }          游标 v2: { fileIndex: 1, hitIndex: 2 }
体积:   固定 topK 条             体积:   字符预算制（渲染后 ~4000 字）
```

硬规则：

- **一页不跨文件**：装不下的组截断，游标停在组内断点，下页从该组续读。
- **预算按实际渲染字符累计**：从游标位置顺序逐命中生成 excerpt，累计到预算上限即切页（惰性求值，不需要预估体积）。
- **确定性排序**：文件组间按命中数降序、同数按路径字典序；组内按行号升序。翻页重扫后排序稳定（前提：库内容不变）。

## 4. 数据契约 v2

### 4.1 类型（`src/types.ts`）

`SearchHit` 不变。新增与调整：

```ts
export type SearchFileGroup = {
  path: string
  format: EntryFormat            // 'md' | 'csv'，Client 卡片图标用
  totalHits: number              // 该文件命中总数（rg 原始计数）
  groupHeader?: string           // CSV 专用：「列: 编号 | 甲方 | 金额」，组头只渲染一次
  hits: SearchHit[]              // 本页返回的命中（组内行号升序）
}

export type SearchResult = {
  files: SearchFileGroup[]        // 本页文件组
  totalFiles: number             // 命中文件总数
  totalHits: number              // 命中总数（scanComplete=false 时为下限）
  restFiles?: Array<{ path: string; count: number }>  // 未展示文件+计数，前 8 个
  warnings: string[]
  scanComplete: boolean
  hasMore: boolean
  nextCursor?: string
}
```

`SearchInput` 调整：`topK` 移除，`offset` 替换为 `cursor 位置 { fileIndex, hitIndex }`，新增 `path?: string`（明细档锁定单文件）。

### 4.2 `SearchHit.n` 语义变化

从「页内序号」改为**整个查询的全局序号**（跨页连续）：`n = 前序所有组 totalHits 之和 + 组内序`。翻页重扫时可计算。收益：跨页引用编号不冲突；`isSamePreviewHit` 比较逻辑不受影响。

### 4.3 `kb_search` 工具入参（`src/tools.ts` schema）

| 参数 | 变化 | 说明 |
|------|------|------|
| `baseId` / `query` / `aliases` / `category` / `cursor` | 不变 | — |
| `path` | **新增** | 明细档：锁定单文件（类目内相对路径，须落在 rootDir 内，复用 containment + 符号链接检查）。与 `category` 可并用（path 相对 category 根） |
| `topK` | **移除** | 体积改由字符预算控制；schema 描述同步更新，AI 读描述自适应 |

输出 schema：`hits` 平铺改为 `files` 分组 + 概览字段；`presentationMeta` 同步改传分组结构（Host/Client 同包同发，无版本漂移，不做平铺兼容层）。

`/kb search` 命令行入口（`src/commands.ts`）为调试通道：新增 `--path` / `--cursor` flag 转发，其余不变。

## 5. 游标 v2（`src/search-cursor.ts`）

```ts
type SearchCursorPayload = {
  version: 2
  fileIndex: number   // 已完整消费的文件组数（明细档恒为 0）
  hitIndex: number    // 当前文件组内已消费的命中数
  queryKey: string    // sha256({ baseId, rootDir, terms, path? })；明细档把 path 纳入指纹
}
```

- v1 游标（version 1）在解码时因版本不匹配走现有「搜索游标无效或已过期」错误路径，无需迁移。
- 换词、换类目、换库、明细档与列表档互串 → queryKey 不匹配 → 同样报游标无效。
- 已知限制（与现状一致）：无状态游标，翻页间文件被修改会导致组边界漂移；预览侧已有 `sourceFingerprint` 失效保护兜底。

## 6. Host 管线（`src/search.ts` 重构 + `src/search-groups.ts` 新增）

### 6.1 主流程

```
searchBase(入参校验、category 解析、游标解码)
  1. 重跑 rg（参数不变：--json --column --max-count --max-filesize + searchGlobs + terms）
  2. parseRg → match 元数据（path/line/column），不读文件
  3. 按文件分组计数 + 确定性排序（命中数降序，同数字典序）→ 全部只留元数据
  4. 从游标 {fileIndex, hitIndex} 起，惰性逐组逐命中生成 excerpt：
     - 该组首个命中时才 readForSearch 该文件（fileCache 复用）
     - 累计渲染字符到 SEARCH_PAGE_MAX_CHARS 即切页
  5. 概览统计：totalFiles / totalHits / restFiles（未进本页的组，取前 8 个）
  6. hasMore = 本页终点之前还有组或组内还有命中
  7. nextCursor = { fileIndex, hitIndex } 断点
```

### 6.2 「只读本页文件」

被跳过的文件组完全不 `readForSearch`（CSV 不解析），翻页成本从「全量命中文件解析」降到「本页 1~2 个文件」。边界情况：切页点落在组首时，会多读一个最终未收录的文件（为计算其 excerpt 体积），最多一个，可接受。

### 6.3 两档制

| 维度 | 列表档（默认，无 `path`） | 明细档（带 `path`） |
|------|--------------------------|---------------------|
| 范围 | 全部命中文件 | 单文件全量命中 |
| MD excerpt 半径 | `SEARCH_LIST_CONTEXT = 2`（命中行 ±2） | `SEARCH_CONTEXT = 8`（现状） |
| CSV excerpt | 仅命中记录（`列名: 值`），表头提升为 `groupHeader` | 命中记录 + `SEARCH_LIST_CONTEXT` 条相邻记录，表头同样进组头 |
| 合并策略 | 所有格式统一**重叠合并**（MD 相邻不重叠的行各自保留；CSV 同记录多行命中收敛一条） | MD 相邻合并（现有 `mergeAdjacent` + `mergeNeighbors:true` 语义）；CSV 保持记录边界（`mergeNeighbors:false`） |
| 体积 | 受 `SEARCH_PAGE_MAX_CHARS` 预算约束 | 同样受预算约束，超限组内截断 + 游标续页 |
| 文件不存在/无命中 | — | 返回空 `files`，`totalFiles=0`，由渲染层提示「该文件无命中」 |

`diversify`（文件轮转打散）**移除**：多文件曝光的职责由概览 + restFiles 清单取代，AI 获得的信息只多不少。

### 6.4 新常量（`src/identity.ts`）

```ts
export const SEARCH_PAGE_MAX_CHARS = 4000   // 每页渲染字符预算（含组头，不含概览尾注）
export const SEARCH_LIST_CONTEXT = 2        // 列表档 MD 上下文半径 / CSV 相邻记录数
export const SEARCH_REST_FILES_LIMIT = 8    // restFiles 最多列出的未展示文件数
```

`DEFAULT_TOP_K` / `MAX_TOP_K` 删除（不再有条数语义）。

## 7. CSV 与 MD 的差异性

差异全部封装在 `SearchDocument` 层（`src/content/shared/search-document.ts`），分页器与渲染器不感知格式：

| 维度 | MD | CSV |
|------|----|-----|
| 记录单元 | 物理行 | 数据记录（可跨物理行） |
| 列表档 excerpt | 命中行 ±2 行小窗口 | 仅命中记录；**表头进 `groupHeader` 只渲染一次** |
| 去重/合并 | 重叠区间合并 | 同记录多行命中合并为一条（重叠合并） |
| 组头 | 无 | `groupHeader = formatHeaderLine(headers)`，excerpt 记录行去掉重复表头前缀 |
| 解析失败 | — | 已有 `csv_parse_fallback` 降级物理行文档，行为不变 |

实现要点：

1. `SearchDocument` 增加可选 `groupHeader?: string`；CSV 文档在 `createCsvSearchDocument` 时产出，MD 为 `undefined`。
2. `formatHeaderLine` 从 `csv/server/search-excerpt.ts` 复用（已是模块内函数，导出即可）。
3. CSV 列表档 `excerptAt(line, 0)` 返回单记录；`matchedExcerpt` 不变（仍是 `列名: 值` 单行，Client 现有 `parseLabeledFields` 拆字段逻辑直接可用）。
4. `mergeNeighbors: false` 的「只合并重叠」半边逻辑复用于列表档统一合并规则。

体积收益示例：一页 10 条 CSV 命中，表头从重复 10 次变为 1 次；单条记录体积减半以上。

## 8. AI 文本渲染（`src/render-search.ts`，从 tools.ts 拆出）

`renderSearchResult` 新格式（text block，给模型的正文）：

```
【命中概览】3 个文件 · 12 条命中 · 本页 5 条

1. 合同/2024/供应商合同.md（3/3 条）

若乙方违约，甲方可解除合同并收取违约金。

[4] L5
名称: 第4条 | 状态: 重复值
```

- 工具 description 同步改写：「结果按文件分组，一页不跨文件；概览含未展示文件清单；需深读单文件时传 path（来自命中路径或未展示清单）」。

## 9. Client 命中卡与预览

### 9.1 命中卡（`src/client/toolview/KbSearchView.tsx`）

从平铺列表改为组渲染：

```
┌ 概览条：3 个文件 · 12 条命中 · 本页 5 条 ────── zy-search-overview ┐
├ ▤ 合同/2024/供应商合同.md  [3 条] ──────────── zy-file-group 头 ──┤
│  [1] 合同/2024/供应商合同.md:L15   命中文本…   ← zy-hit 卡不变     │
├ ▦ ledger.csv  [2/5 条]  列: 名称 | 状态 ────── CSV 组头含表头 ────┤
│  [4] ledger.csv:L5  名称: 第4条 | 状态: 重复值  ← zy-hit 卡不变    │
├ 底部：还有 c.md(12)、d.md(5) 等 10 个文件未展示                    │
│ hasMore + scanComplete 提示（现有文案保留）                         │
└────────────────────────────────────────────────────────────────────┘
```

- 命中卡本体（`zy-hit`、CitationTag、选中态、键盘可达）不动；组头新增 `zy-file-group` 样式（`--dsw-alias-*` token，遵守 `zy-<component>-<element>` 命名）。
- `extractSearchHits` 改为 `extractFileGroups`：新增 `isSearchFileGroup` 校验（结构收窄），`isSearchHit` 校验保留复用。
- 列表 key 使用业务 key（组 `path`；命中沿用现有 `${n}-${path}-${startLine}-${matchLine}`）。
- 组头不做预览入口（见非目标）；空态/加载态/错误态覆盖：概览条在 `files` 为空时显示「无命中」，`isError` 走现有失败文案。

### 9.2 预览（零改动，已验证）

链路：`zy-hit` 点击 → `preview.select({ baseId, hit })` → [preview-state.ts] 状态机（abort 旧请求、loading、openDetails）→ `read` RPC（`view:'search-hit'` + `matchLine / matchColumnByte / sourceFingerprint`）→ Host `readEntry`（MD 行窗 / CSV 记录窗 + [preview-focus.ts] 指纹比对）→ details 分区渲染 `EntryPreviewContent`，失效/失败降级 `matchedExcerptLine(hit)`。

预览是独立按需读盘 RPC，**不消费搜索结果里的 excerpt**：

- 列表档 excerpt 瘦身只影响 AI 上下文；用户点击后看到的预览永远是 Host 现读的完整原文窗口。
- 预览契约字段全保留 → 点击处理一行不改；指纹失效保护天然还在（「文件已变化，显示命中片段」）。
- 唯一微调：失败态兜底显示 `matchedExcerptLine(hit)`（单行，优先 `matchedExcerpt`）——列表档下该值语义不变。

## 13. 已知限制与后续方向

- 无状态游标：翻页间库内容变更导致组边界漂移（与现状一致；预览侧指纹兜底）。后续可做「游标快照首次分组的文件清单」校验，检测到漂移时给出「结果已变化，建议重新检索」。
- `totalHits` 在 `scanComplete=false` 时是下限（rg stdout 截断 / 单文件 max-count 截断），概览文案需带「至少」语义。
- restFiles 只列前 8 个 + 总数，AI 需要完整清单时可传 `path` 逐个取，或换更精确的词。
- 预算常量 4000 字是初值，待真实库压测量化后可调。
