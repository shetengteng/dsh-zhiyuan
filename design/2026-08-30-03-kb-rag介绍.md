# 社区插件介绍：kb-rag（本机论文库）

> 日期：2026-08-30  
> 序号：03  
> 对象：Breeze136 的 DeepSeek Harness 插件 **kb-rag**（npm 包名 `dsh-kb-rag`）  
> 定位：电脑上的 PDF / Zotero 文献；能搜、能精排、回答带 DOI 或文件名。索引和「懂意思」的模型都在本机。

## 1. 一句话

给读论文的人用的：**一堆 PDF（以及 Zotero 文献库）变成能问的本机库**。问的是「那句话在哪篇、哪一节」，答的是带 DOI 或文件名的坐标，不是公司文档网盘。

和 dsh-library 一样都是本机知识库，但垂直在 **论文结构**（摘要、方法、图注、DOI 更重要），搜索质量靠本机的 bge 模型，不是按字凑的 hash。

---

## 2. 它怎么跑起来

DSH 自己不会跑向量库。这个插件把重活放在旁边一个常驻的 Python 程序里：

```text
DSH 里的 AI
    │  调工具
    ▼
插件（薄薄一层 JS：8 个工具 + 拉起 Python + 用文本行对话）
    │
    ▼
Python 引擎（模型加载一次，之后问一次大约一秒内）
    ├─ 导入：文件指纹一样就跳过 → 从 PDF 抽字 → 按章节切开 → 用 bge 做成「按意思」的数字
    ├─ 搜索：先按条件缩小 → 按字和按意思两路 → 合成 → 再精排 → 段落 + 出处
    └─ 存在当前项目的 `.kb/kb.sqlite` 里
```

作者故意 **不做管理页面**：导入、搜索、清空都在对话里完成。他们认为文献库的界面就是对话，面板是给「要人点着管理」的产品用的。

许可证 MIT。npm 包声明了 DSH 插件包，一条 `dsh plugin add` 就能激活 JS 这一面（Python 还要另装）。

## 3. 能做什么

### 3.1 八个工具

| 工具 | 人话 | 可以这么说 |
|------|------|------------|
| `kb_ingest` | 导入文件或文件夹，改过的才重做，重复的跳过 | 「把 papers 目录导入」 |
| `kb_zotero` | 从 Zotero 拉元数据和 PDF | 「同步 Zotero」 |
| `kb_search` | 搜索，返回段落和出处 | 「搜石墨烯 CVD」 |
| `kb_rag` | 按规定格式、必须带引用的问答 | 「畴壁导电机制是什么？」 |
| `kb_scope` | 只搜库 / 库加网页 / 只网页；还有「证据不够就说没有」的严格模式 | 「切到严格模式」 |
| `kb_dedup` | 清掉重复 | 「去重」 |
| `kb_clear` | 清空（会确认） | 「清空知识库」 |
| `kb_stats` | 库里有多少 | 「库里有什么」 |

和 dsh-library 的差别：library 倾向「先搜索，再由当前对话模型自己写」；kb-rag 多一条 **规定了引用格式** 的问答工具，并且严格模式下证据不够就承认库里没有。

### 3.2 它为什么更像「搜论文」而不像「搜任意文档」

- 切开时认得章节：摘要更重要、方法其次；图注单独成块。普通文章则按段落切。  
- 按字搜索（中文按两个字一组）和按意思搜索一起用，再按章节重要性加权。  
- 精排：用另一个模型把前 20 段收到前 3 段。这个模型没有时，退到较弱的一档。  
- 同一份文件（内容指纹一样）再导入会跳过，官方说同目录重跑能快几十倍。  
- 同样的问题和过滤条件会缓存；再导入新文件会作废缓存。  
- 答完可以提示「库里还有同作者 / 同年份 / 主题接近的」以及「还缺什么」。  
- 有 DOI 就做成链接；没有就写成「作者、年、文件名」。

### 3.3 作者公布的速度（来自上游说明，本机未复测）

| 项 | 数字 |
|----|------|
| 导入 | 242 个 PDF/Word、1.8GB，大约 86 秒（每篇大约 0.35 秒） |
| 同目录再跑一遍 | 大约 2 秒 |
| 已经热起来的查询 | 大约 2 万小段时 0.4～1.3 秒（含精排） |
| 样例库 | 209 篇 / 约 2 万小段 / 单个 SQLite 文件 |

作者认为：大约 2 万小段，用比较朴素的按字 + 向量扫描还够用；到几十万小段再换更专业的索引。这和「很多 TB」不是同一档，见 31-01。

## 4. 离线？要先下模型

| 问题 | 事实 |
|------|------|
| 文档会不会传到公网 | 不会。抽字、按意思编码、精排都在你电脑上。 |
| 装上就能拔网线用吗 | **第一次**要从 HuggingFace（或国内镜像）把 bge 模型下到本机。下完之后，搜索可以不再碰网。 |
| 还要什么 | **Python** 以及 PyMuPDF、sentence-transformers 一类包。 |
| 会不会自动 pip 安装 | 默认只在日志里打印安装命令；设了环境变量才会由插件按固定参数自装。 |
| 默认模型 | 中文小模型做「按意思」；另有一个精排模型。 |

这和 dsh-library「hash、零下载」不是同一档离线：kb-rag 是 **模型已经落在本机之后** 的离线，不是「装上插件立刻不产生任何外网流量」。

数据放在当前项目的 `.kb/kb.sqlite`。卸插件时只应删它生成的索引，**不要动你的 PDF 和 Zotero 原库**。

## 5. 安装

需要本机 PATH 里有 pnpm：

```sh
dsh plugin --profile web add dsh-kb-rag
```

想一次把 Python 依赖、冒烟测试、激活、以及可选的模型预下载做掉：

```sh
npx --yes --package dsh-kb-rag -c "dsh-kb-rag-install --profile web"
```

然后重启 DSH、开新对话，八个工具才会出现。  
网络受限时设 `HF_ENDPOINT=https://hf-mirror.com`。

上游自己说的限制：PDF 缺元数据时年份可能抽错（用 Zotero 可以盖过去）；关键词扫描还在内存里做，库再大要换索引；路线图里的查询翻译、图注 OCR、引文网络还不是已交付能力。

## 6. 和 dsh-library、和我们方案

| | dsh-library | kb-rag |
|--|-------------|--------|
| 资料 | md/txt 路径 | PDF/Word 文件夹、Zotero |
| 引擎 | 纯 JS + DSH 小仓库 | JS 薄层 + **Python 常驻进程** |
| 默认「懂意思」 | hash（可换 Ollama） | 本机 bge + 精排 |
| 界面 | 无 | 故意没有管理面板 |
| 给谁用 | 通用文档、规范 | 学术文献 |
| 安装麻烦程度 | 低 | 高（Python、模型下载、项目里的 sqlite） |

对我们意味着：

- **不要**把 kb-rag 当成「通用本机知识库」的底座。Python + 要从网上下的模型，和「一条命令装上就能用」不合。我们阶段 1 仍建议纯 JS（或可选本机 Ollama），PDF 往后放。  
- **值得学**：按章节切、文件指纹跳过重复、严格模式「库里没有就说没有」、出处必须能点回原文。  
- 如果你本人只是要搜自己的论文、能接受 Python，**可以直接装来用**，不必等自研。自研要覆盖的是「多种资料 + 给人点的管理页 + 以后自己的云」，不是再做一个论文垂直引擎。
