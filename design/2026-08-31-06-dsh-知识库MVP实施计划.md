# DSH 知识库 MVP 实施计划

> 日期：2026-08-31  
> 序号：06（同日 02 文件夹 grep；03 SQLite FTS；04 导入与分类；05 交互布局）  
> 定位：把 02 / 03 / 04 已经定下的 MVP 拆成可开工的模块、契约、里程碑和验收。05 只决定界面挂在哪，不改产品边界。  
> 不改：工具名、漏斗（先选择知识库再搜）、原文只在文件夹。  
> 对外用语：知识库（原「柜」）；类目（原「格子」，即子文件夹）。界面与 Skill 不写开柜、落柜。

---

## 1. 一句话

做一个 DSH 插件 `dsh-knowledge`：人显式新建知识库、把本机 md/txt 导入指定库；查询时先选择知识库，再用 3～8 个关键词一次 grep；命中带文件和片段交给当前对话模型写答案。

**正文在文件夹里。MVP 没有检索目录（SQLite FTS 后做，见 03）。类目就是子文件夹（见 04）。**

---

## 2. 范围：做 / 不做

对照 02 §MVP 技术选型、03「什么时候才需要这本目录」、04「第一版明确不做」、05「第一版明确不做」。

### 做（本计划交出去的）

| 面 | 内容 | 依据 |
|----|------|------|
| 货架 | `bases/<库>/<类目>/文件.md`；导入是拷贝，不是记外链 | 02 |
| 库卡片 | 建库时写卡片：id / 标题 / 描述 / 别名；写进 `catalog.json` | 04 |
| 导入 | 人指定 `baseId` + `destCategory`；缺类目 mkdir -p；缺库拒绝 | 04 |
| 检索 | 选库 → 可选类目 → 一次 3～8 词 OR grep → 截 8～20 段 | 02 |
| 工具 | `kb_list_bases` / `kb_ingest` / `kb_search`；斜杠 `/kb ingest` `/kb status` | 02、04 |
| 工作台 | 设置左侧 `settings.section`「知识库」：库列表、树、导入、偏好、试搜 | 05 |
| 对话 | `kb_search` 命中卡；Skill：没点名库先列库，没命中不得说「根据知识库」 | 02、05 |
| 离线 | 导入和 grep 不访问外网 | 02、01 §1.3 |

### 不做（写进代码注释也禁止先做）

| 不做 | 若做了会怎样 | 何时再开 |
|------|----------------|----------|
| SQLite FTS / 切段建目录 | 和「个人量级当场 grep」相反；维护第二份状态 | 约 2000 篇或明确要排序，见 03 |
| 把全文写入任何数据库 | 两份正文，文件夹不再是唯一货 | 永不作为默认 |
| 导入时模型自动选库 / 自动建库 / 自动归类 | 放错知识库 = 漏斗永远扫不到 | 04 ③ `kb_suggest_placement`，确认后才拷 |
| PDF / DOCX / 监视源目录自动入库 | 第一版承诺面过大；写文件 ≠ 进库 | 下一小版；监视永不做 |
| hash 假向量、默认打网上嵌入 | 破坏离线；换词 grep 已覆盖个人量级 | 本机 Ollama 另开，且可关 |
| `kb_ask` / 云 HTTP / 关系 / 实体 | 阶段 2 和 06 ②③ | 搜索闭环之后 |
| 主左侧一级「知识库」、对话顶栏/输入框芯片 | 没有官方座位或第一版会再长一套管理 UI | 05 后续扩展 |
| 改 DSH 外壳、网页自己扫文件、把项目 grep 冒充知识库 | 卸载清不掉；和 05 冲突 | 永不 |

**03 对本计划的含义：** 读懂「后做要建哪些表」，但 **本里程碑一行 SQL 都不要写**。检索口留成函数，以后把 grep 换成查目录，工具参数不变。

## 3. 形态与插入点

一个 npm 包，两半一起装（01 §2.1，不改）。

```
dsh-knowledge/
├── package.json
├── cordis.patch.yml
├── src/                          # 主进程：唯一能读写知识库的一侧
│   ├── index.ts                  # 注册：设置 / 工具 / 命令 / skill
│   ├── paths.ts                  # 插件数据根、路径规范化与逃逸检查
│   ├── catalog.ts                # catalog.json 读写
│   ├── bases.ts                  # 建库 / 列库 / 扫类目树 / 约多少篇
│   ├── ingest.ts                 # 拷贝、指纹、冲突、mkdir
│   ├── search.ts                 # 调打包 ripgrep，收段
│   ├── tools.ts                  # kb_* 参数与返回
│   ├── commands.ts               # /kb ingest、/kb status
│   ├── skill.ts                  # 选库 / 换一次词 / 出处硬规则
│   └── jobs.ts                   # 导入单队列；失败项给人看
└── src/client/
    ├── index.ts
    ├── settings/                 # 工作台：B1 库+树、B2 建库、B3 导入、B4 偏好
    └── toolview/                 # kb_search 命中卡
```

| 跑在哪 | 干什么 | 不要干什么 |
|--------|--------|------------|
| 主进程 | 建目录、拷文件、grep、登记、工具 | 把正文塞进设置 JSON |
| 网页 | 工作台、命中卡、发命令 | 自己扫磁盘、当网盘拖大文件 |

数据根用插件数据目录（实现时走 DSH 官方 API），逻辑布局与 02 一致：

```text
<plugin-data>/dsh-knowledge/
├── catalog.json                  # 库卡片 + 上次用哪个；不是正文
├── state.json                    # 可选：指纹、失败项、进行中任务
└── bases/
    ├── work/contracts/供应商.md
    └── life/
```

`catalog.json` 没有也能扫 `bases/` 列出库；**没有卡片时描述为空，模型容易选错库，创建入口必须让人写描述。**

## 4. 契约（阶段 1 定死，换 FTS 不得改）

### 4.1 catalog.json

```json
{
  "version": 1,
  "lastUsedBaseId": "work",
  "prefs": {
    "defaultBaseId": "work",
    "maxFileBytes": 5242880,
    "maxBaseBytes": 10737418240
  },
  "bases": [
    {
      "id": "work",
      "title": "工作库",
      "description": "公司合同、会议纪要、供应商往来。问条款、纪要、交付开这个库。个人账单、家庭、医疗不要放。",
      "aliases": ["工作", "公司", "合同库"],
      "createdAt": 0,
      "lastUsedAt": 0
    }
  ]
}
```

- `id`：创建后不可改；路径 `bases/<id>/`。
- `description`：创建时必填，可短。给 LLM 选库，不要写文件清单。
- 篇数不持久化也可以：列库时扫该库下 md/txt 计数。

### 4.2 建库

入口：工作台「新建知识库」，或主进程内部 `createBase`（导入路径 **不** 调它）。

| 字段 | 必填 | 校验 |
|------|------|------|
| id | 是 | `[a-z0-9][a-z0-9_-]{0,63}`；已存在则拒绝 |
| title | 是 | 非空 |
| description | 是 | 非空；建议 ≤ 500 字 |
| aliases | 否 | 字符串数组，去空白 |

成功：`mkdir bases/<id>/`，写入 `catalog.json`。不创建默认类目。

**改库：** 工作台当前库标题旁「编辑」。可改 `title` / `description` / `aliases`；**id 和路径不能改。** 主进程 `updateBase(id, patch)`。

**删库 / 删文件：** 左侧库列表悬停垃圾桶，或编辑页脚「删除」，去掉整个库（`bases/<id>/` 和 catalog 项）。树里悬停删除文件或类目。均需确认。删的是知识库副本，不是用户指定的源路径。主进程 `deleteBase` / `deleteEntry`。

**预览：** 点 md 打开原文，可改可存；关闭用右上角 ×。主进程 `readEntry` / `writeEntry`。

### 4.3 工具

**`kb_list_bases`**

无参数。返回每个库：`id`、`title`、`description`、`aliases`、类目名列表、约多少篇、是否 lastUsed。  
**不含文件名、不含正文。** 需要树时另调列类目（工作台用同一主进程函数；模型需要时再加 `kb_list_categories(baseId)`，MVP 可先让工作台走命令、模型只靠 list_bases 的类目名）。

**`kb_ingest`**

| 参数 | MVP | 说明 |
|------|-----|------|
| baseId | 必填 | 库必须已存在，否则失败并提示先建库 |
| sourcePath | 必填 | 本机文件或文件夹；只读源 |
| destCategory | 必填语义 | 相对路径；空 = 库根（仅保留源树时合理） |
| preserveTree | 默认 false | 源是文件夹时是否保留相对子目录 |
| createMissing | 默认 true | 只 mkdir destCategory 链，不建新库 |
| onConflict | 默认 skip | 指纹相同跳过；同名不同内容改名 `name-2.md` |

返回：进了哪个库、哪些相对路径、新建了哪些文件夹、跳过/失败条数。  
`suggestOnly` **不实现**。

**`kb_search`**

| 参数 | MVP | 说明 |
|------|-----|------|
| baseId | 必填 | 禁止省略后扫全部 `bases/` |
| query | 必填 | 主关键词 |
| aliases | 建议 | 3～8 个；插件与 query 合并去重后一次 OR |
| category | 可选 | 对上子文件夹则只扫那一层；对不上则本库全扫 |
| topK | 默认 12，上限 20 | 打散同一篇后留下的段数 |

返回每条：`path`（库内相对）、`startLine`、`endLine`、`excerpt`、`[n]`。无命中返回空列表，**不要编一段「可能相关」**。

等价检索（实现，不是给模型看的）：

```bash
rg -n -C 8 --glob '*.md' --glob '*.txt' -e 词1 -e 词2 … <bases>/<baseId>/<category或根>
```

收段规则：命中行 ±8；同一文件相邻命中合并；打散同一篇，避免 20 段全来自一篇。

### 4.4 斜杠命令（与工具同一套字段）

| 命令 | 行为 |
|------|------|
| `/kb ingest <path> --base <id> --to <destCategory>` | `--to` 缺则问一句，或用该库上次类目 |
| `/kb status` | 队列：进行中 / 失败；断连后仍能看见失败 |

不单独做 `/kb search` 当主路径：人用工作台「试搜」，模型用 `kb_search`。

### 4.5 Skill / 硬规则（写进 skill 正文，验收要勾）

1. 用户没点名库：必须先 `kb_list_bases`，用描述和别名选一个 `baseId`；两个都像就问人，禁止两个都搜，禁止默认扫全部 bases。
2. 换词只做一次，放进同一次 `kb_search` 的 `aliases`（3～8），禁止连调三十轮。
3. 没命中不得说「根据知识库」；命中必须带文件和片段 `[n]`。
4. 当前项目里的 `grep` / `glob` **不算** 知识库检索。
5. 导入：用户话里没有库名就先问；禁止猜一个新库；禁止无 destCategory 就散落。

## 5. 导入路径安全（04 原样执行）

写入前必须过，失败不落盘：

- `destCategory` 规范化：去空段、去首尾 `/`。允许中文。建议深度 ≤ 4，更深只提示不禁止。
- 解析后的绝对路径必须仍在 `bases/<baseId>/` 下。拒绝 `..`、绝对路径、符号链接逃出。
- 合法：`合同/2024`、`contracts`、`_inbox`、空（库根）。非法：`../life`、`/etc`、`work/../../life`。
- 只读用户指定的 `sourcePath`；写入只限插件数据目录。
- 后缀白名单：`.md` `.txt` `.markdown`。单文件 5 MB；单库文字 10 GB，超过拒绝本批导入。
- `_inbox` 仅当人明确选「先堆着」才创建，不当默认。

指纹：文件内容 sha256。相同指纹在同一库已存在 → skip。同名不同指纹 → 改名，不覆盖。

导入走单队列（01 §2.3）：同一时刻只跑一批拷贝，网页只显示进度，不以「点了就开始」抢主进程。

## 6. 网页工作台（05 页面 B，第一版就要有）

挂 `settings.section`，id=`knowledge`，label=知识库。插件配置窄卡 **不** 再做一份工作台。

| 页 | 对应 05 | 主进程能力 |
|----|---------|------------|
| 库 | B1 左库右树：库卡片、类目树、任务条、试搜 | list / 扫树 / search / 打开导入、编辑 |
| 新建 | B2 | createBase |
| 编辑 | B2b：id 只读；改标题、描述、别名；可删库 | updateBase / deleteBase |
| 预览 | B5：点 md 可改原文；可存、可删；× 关闭 | readEntry / writeEntry / deleteEntry |
| 导入 | B3：选文件夹/文件为主，也可填路径；类目 destCategory；mkdir 开关；保留源树 | ingest |
| 偏好 | B4：默认库、5MB / 10GB；解析器 md/txt 勾上，其余置灰 | 读写 prefs |
| 关于 | B6：使用说明（建库 / 导入 / 自然语言问） | 静态文案 |

命中卡（对话里，不是工作台）：路径、片段、`[n]`。点卡打开只读预览，滚到该句并高亮。不能改。不跳设置 section。

试搜：工作台一个输入框直接调 `search()`，不经过模型。用来验收「拔网线还能搜」。

## 7. 里程碑（前一档没过，不进下一档）

原则：先主进程可测，再挂界面，再把工具交给模型。grep 比 FTS 简单，不要把 01 的 P5 Ollama / P6 PDF 捆进来。

| 档 | 交付 | 怎样算过 | 主要文件 |
|----|------|----------|----------|
| **M0 空包** | 两半能装上 | `dsh plugin add` 后配置里有这一行；主进程和网页都加载；卸载不崩 | `package.json`、`index.ts` ×2 |
| **M1 建库** | 建库 + 列库 | 创建 `work` 后磁盘上有 `bases/work/` 和 catalog 卡片；重启还在；id 重复拒绝；导入路径不能建库 | `catalog.ts`、`bases.ts`、`paths.ts` |
| **M2 导入** | 拷文件 | 指定 `合同/2024` 不存在则创建再拷；`../life` 拒绝；同指纹 skip；缺库报错；断网仍成功 | `ingest.ts`、`jobs.ts` |
| **M3 检索** | grep 搜索 | 只扫该库；aliases 一次 OR；返回带行号的段；空库空结果；试搜不联网 | `search.ts` |
| **M4 工作台** | 设置 section | 能建库、编辑/删除、预览 md、看树、导入、偏好、搜索；与 M1–M3 同一套函数 | `src/client/settings/` |
| **M5 给 AI** | 工具 + Skill + 命中卡 + `/kb` | 对话问库里的事实会 `list_bases` 再一次 `kb_search`；命中带 `[n]`；未点名库不扫全库 | `tools.ts`、`skill.ts`、`commands.ts`、`toolview/` |

**M0–M5 勾完 = 可发布的个人 MVP。** 之后才允许开：FTS（03）、推荐导入位置（04 ③）、PDF、对话区芯片（05 后续）。

建议工期（一人、已做过双面插件，供排期不是承诺）：M0–M1 两天；M2–M3 三到四天；M4 三天；M5 两天；说明与离线验收一天。

## 8. 建议实现顺序（模块内部）

不要先画完整 UI 再倒逼主进程。

1. **`paths.ts`**：数据根、`resolveDest(baseId, destCategory)`、symlink / `..` 测试用例先写。
2. **`catalog.ts` + `bases.ts`**：无界面用 node 脚本或临时命令建一个库。
3. **`ingest.ts`**：单文件 → 文件夹 + preserveTree → 冲突。队列放 `jobs.ts`，M2 可以先同步拷、M4 再显示进度。
4. **`search.ts`**：对测试库跑固定 5 问（见下），锁住「一次多词、截段、打散」。
5. **`tools.ts` / `commands.ts` / `skill.ts`**：参数表与 4.3 逐字对齐。
6. **网页**：先 B2+B1 只读树，再 B3 导入，再 B4，最后命中卡。

ripgrep：与 DSH 内核查代码同一类，用打包好的二进制，不要自己写递归读文件当搜索。

## 9. 验收用例（可当手工清单）

### 9.1 走一遍（02 + 04 原文场景）

1. 新建库 `work`，描述按 04 工作库那两句，别名：工作、公司。
2. 导入 `~/Downloads/供应商合同.md`，`--to 合同/2024`。类目原先不存在。
3. 磁盘为 `bases/work/合同/2024/供应商合同.md`。源文件未被改。
4. 问：「去年那个供应商合同的违约条款写了什么？」模型先 list_bases 再 `kb_search(baseId=work, category=合同或contracts, aliases=[违约,解约,termination,违约金,…])`。
5. 命中来自该文件，带行号；会议类目（若有）未被扫。
6. 拔网线：重复 2 和试搜，仍成功。对话能不能写成完整答案，取决于有没有本地模型——设置页用一句话说清。

### 9.2 必须失败

| 操作 | 期望 |
|------|------|
| ingest 到不存在的 `life` | 拒绝，提示先建库 |
| destCategory=`../life` | 拒绝，无文件写出 |
| 对当前代码项目 grep 后回答「根据知识库」 | Skill 禁止；验收对话抽查 |
| `kb_search` 不带 baseId | 工具校验失败 |
| 一次 aliases 30 个、或连调 search 很多轮 | Skill 禁止；实现可截断到 8 个并警告 |
| 单文件 > 5 MB | 该文件失败，其他可继续 |
| 空库搜索 | 空列表，答案不得虚构库内条款 |

### 9.3 换档信号（本版不实现，只记录）

- 单库约 2000 篇，grep 明显变慢 → 开 03 FTS。
- 明确要「哪段更相关」→ 开 03。
- 换说法仍经常漏且已有本机模型 → 再谈语义，不在本计划。

## 10. 和后做 FTS 的接缝（只留口，不写表）

```ts
interface SearchEngine {
  search(input: {
    baseId: string
    rootDir: string          // bases/<id>/ 或再拼 category
    terms: string[]          // query + aliases，已去重，3～8
    topK: number
  }): Promise<SearchHit[]>
}
```

MVP：`RipgrepSearchEngine`。以后：`FtsSearchEngine` 查 `catalog.sqlite`，再用 `startLine/endLine` **打开文件夹里的 md**。  
`kb_search` 参数、命中字段、Skill 漏斗都不改。  
禁止为了「以后方便」提前建 `chunks` 表或在 ingest 时切 bigram。

## 11. 风险与默认值

| 风险 | 处理 |
|------|------|
| 模型不调 list_bases 直接 search | Skill 写死；工具强制 baseId |
| 类目文件夹名对不上问题里的词 | 对不上就本库全扫（02 第 1 步），不要猜 |
| 中文路径 / 空格 | rg 与拷贝都按字面路径；测试用「合同/2024」 |
| DSH 座位改名 | 钉死目标 DSH 版本；对照 lumina / dsh-market 的 `settings.section` |
| 和 dsh-library 看起来重复 | 说明差异：多库卡片、人指定导入位置、工作台、预留同一套 `kb_*` 换引擎 |
