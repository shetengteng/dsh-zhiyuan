## 1. 一句话

不要「只把 `.csv` 加进白名单再 `copyFile`」。中文 Excel 默认 CSV 经常是 GBK，原样拷进库后 ripgrep 当二进制跳过或乱码，模型等于没读到。

当前进度：

1. **CSV（已实现）**：导入即编码归一——严格解码、换行归一、UTF-8+BOM 落盘，原始字节不留库；单文件有效上限 `min(prefs.maxFileBytes, 20 MiB)`，一次性已校验 Buffer 原子写入。库树、篇数、去重、逻辑记录搜索、表格预览与编辑全部可用。
2. **XLSX（已实现）**：经 `@e965/xlsx@0.20.3`（门禁见 §7）在隔离子进程里 `XLSX.read(buffer)` + `sheet_to_csv` 输出一个或多个 CSV。CSV 源不调用 `XLSX.read`。**转出物是库内规范 CSV，落库后与手工导入的 CSV 完全同权：同样的检索、同样的表格编辑，不产生任何「只读来源」标记。**
3. **检索增强（已实现，XLSX 产物天然继承）**：CSV 命中按 RFC 4180 解析为逻辑记录，保留物理行号，按列名生成 excerpt。

库内正文就是 CSV。不转 Markdown。

## 2. 为什么不能只放行后缀（背景）

当年只打算改白名单时的推演，如今仍是 XLSX 接入的依据：

| 只放行后缀 | 实际后果 |
|------------------|----------|
| 导入直接 `copyFile` | GBK 原样进库 |
| 搜索 glob 不含库内后缀 | 就算进了也 **0 命中** |
| 非 UTF-8 文本 | 被 rg 当二进制跳过；`readFile(..., 'utf8')` 拼 excerpt 乱码 |
| excerpt 是生 CSV | 命中在第 80 行时没有表头，模型看见 `甲,120000` 不知道列名 |

AI 没有读整篇的工具，只能吃 excerpt。所以「能读懂」必须在 **落盘编码** 和 **截段改写** 两处保证。前三行问题已由格式路由与编码归一解决；第四行已由列名 excerpt 解决。

做得到的：「甲公司金额多少」→ excerpt 里有 `供应商: 甲公司 | 金额: 120000`。

做不到的：对 2000 行求和、透视。那是换档（`kb_read` / 按行切），本档不写。

## 3. 管道

```
.csv（已实现）                                .xlsx（已实现）
     │                                             │
     ▼                                             ▼
 BOM → UTF-8 → UTF-16 → GB18030 严格解码     XLSX.read(buf, { type: 'buffer' })
     │                                             │
     ▼                                             ▼
 换行归一为 LF                        先作范围/公式预检；每个可导出 sheet：
     │                                sheet_to_csv(...) → 逗号 + LF
     ▼                                             │
     └──────────────────┬──────────────────────────┘
                        ▼
        统一校验后写成 UTF-8+BOM（EF BB BF）
                        ▼
             bases/<id>/<类目>/<名>.csv
                        ▼
        指纹 / 冲突 / 配额对象都是规范化后的 UTF-8 Buffer
                        ▼
         kb_search：glob 由 host-registry.searchGlobs() 派生
         excerpt 按列名改写成「列名: 值」（不要再 XLSX.read）
                        ▼
         表格编辑：readPage / writeContent 复用，保存序列化为逗号 CSV
```

两条源在「统一输出 Buffer」阶段汇合，**不在 `XLSX.read` 汇合**。`sheet_to_csv` 返回 JS 字符串、不带 BOM；BOM 由我们的 `encodeUtf8CsvWithBom` 统一加。xlsx 不要做 GBK 猜测（OOXML 已是 Unicode）。

| 决策 | 取舍 |
|------|------|
| 库里不留 `.xlsx` | 与 DOCX 档一致；grep 只扫文本 |
| `.csv` 不直接 `copyFile` | 已实现：读入、解码归一、复用同一 Buffer 原子写出，避免校验后源文件变化 |
| `.xlsx` 不 `copyFile` | 已实现：子进程转出 CSV 再落库；**不解析、不改格子** |
| 一本工作簿多表 | 每表一个文件：单表用 `原名.csv`；多表用 `原名-表名.csv`；每个都独立可编辑 |
| 指纹哈希 | 已实现：对规范化后的 UTF-8 Buffer；同一份 GBK 与 UTF-8 源可归一 |
| 公式 | 只要缓存计算结果；写成普通文本后编辑器可改；缺缓存的公式整份失败 |
| 图 / 宏 / 透视布局 | 丢掉 |
| 隐藏 sheet / 行 / 列 | 默认不进库并给 warning，避免把用户故意隐藏的数据变成可检索正文 |
| 全部 sheet 隐藏或为空 | 源级结果为 `skipped`（不是成功的零输出），带稳定 warning（`PreparedImport.skipped`） |

md / txt / markdown 仍原样入库，docx 走 01 档转 Markdown。本档不动。

## 4. 库内 CSV 长什么样

所有入库 CSV 统一 **UTF-8 + BOM（`EF BB BF`）+ LF**（[utf8.ts](../../src/formats/shared/utf8.ts)）。读回、预览、检索一律先剥 BOM，否则第一列表头变成 `\uFEFF供应商`，改写 excerpt 会对不上。

- 从 **csv** 来的（已实现）：导入保留源分隔符与引号风格，只做编码 / 换行 / BOM 归一；**表格编辑保存时**由编辑器统一序列化为逗号 CSV（[csv-document.ts](../../src/formats/csv/server/csv-document.ts) 的 `serializeCsvDocument`）。
- 从 **xlsx** 来的（已实现）：`sheet_to_csv` 出逗号分隔、LF 换行，落库即规范形。不改 `00123` / 日期 / `=公式` 文本。

解析契约（已实现，[csv-document.ts](../../src/formats/csv/server/csv-document.ts)）：

1. **输入编码**：BOM → UTF-8 → UTF-16 LE/BE → 假定 GB18030，全部 `{ fatal: true }`；不做无提示的编码猜测——GB18030 回退附 `encoding_assumed_gb18030` warning，运行时不支持 GB18030 返回 `encoding_unsupported`。
2. **输入方言**：分隔符候选为逗号 / 分号 / Tab / 竖线（`DELIMITER_CANDIDATES`），按首条逻辑记录引号外计数取最高者；引号、`""`、引号内分隔符和跨行字段按 RFC 4180 处理；解析错误或记录数对不上时整文件失败（`csv_parse_invalid`），不静默拆列。
3. **规范输出**：编辑保存时固定 UTF-8+BOM、逗号分隔、按需加双引号、LF；保留字段值与空列，不执行公式文本。
4. **边界与指纹**：导入、预览、编辑写回共用 `validateUtf8CsvBytes`；体积、单物理行 64 KiB、控制字符（NUL 拒绝，只放行 tab 与换行）在同一处把关；哈希、配额和落盘都针对最终 Buffer，校验失败不写入。

```csv
供应商,金额,币种
甲公司,120000,CNY
乙公司,98000,CNY
```

### 4.1 编辑契约（XLSX 转出物必须满足）

XLSX → CSV 后可编辑是产品需求，不是附带效果。转出物落库即进入现有编辑路径（[csv-format.ts](../../src/formats/csv/csv-format.ts) 注册的 `readPage` / `writeContent`），因此：

1. `sheet_to_csv` 输出必须能被库内 RFC 4180 解析器无损往返：逗号分隔、LF、字段引号规则与 `serializeCsvDocument` 一致；落库前过同一套 `validateUtf8CsvBytes` 校验。
2. `EntryFormat.Csv` 是唯一库内形态；不新增「xlsx 来源」的只读条目类型。多表拆出的每个 CSV 各自独立编辑。
3. 编辑的 revision 冲突检测、单库 / 单文件配额、原子写、保存时逗号规范化全部复用，不为 XLSX 来源开旁路。
4. 编辑器分页与补丁限制见 [csv-limits.ts](../../src/model/csv-limits.ts)：编辑页 200 行、单次 patch 10000 处、预览窗口 500 行 / 200k 字符。

空表、全空 sheet：跳过，不写文件，warnings 记一句。

隐藏或 VeryHidden sheet：默认跳过，不写文件，warnings 记一句。可见 sheet 的隐藏行/列也默认跳过，并在 `sheet_to_csv` 传 `skipHidden: true`。第一版不提供「导入隐藏数据」的 UI 开关。若所有 sheet 都因此跳过，源级结果为 `skipped`（不是成功的零输出），同时带稳定 warning。

XLSX 硬上限（防一张表撑爆内存 / 拖垮进程；CSV 侧限制由 `csv-limits.ts` 承担）：

| 上限 | 值 | 超了 |
|------|----|------|
| 工作表 | 128（2026-10-04 由 32 上调：真实课表即有 44 张有效 sheet，32 会误伤；上限仅拦病态工作簿，资源风险由单表与总量兜底） | 整份工作簿失败，不落盘 |
| 单表 `!ref` 声明行数 | 2000 | 整份工作簿失败，不落盘 |
| 单表 `!ref` 声明列数 | 40 | 整份工作簿失败，不落盘 |
| 单源转换产物合计 | 20 MB | 整份工作簿失败，不落盘 |
| 转换墙钟 | 30s | 该项失败 |
| 源体积 / 写出体积 | `maxFileBytes` 与 20 MiB 各过一遍 | 该项失败 |

不能把「超过上限」实现为截断后成功：那会使模型检索到一份看似完整、实际缺尾部数据的台账。转换子进程在调用 `sheet_to_csv` 前以 `!ref` 解出的**原始声明范围**检查 workbook / worksheet（不因隐藏行列放宽；对稀疏 dimension 同样生效）；超限则返回结构化失败（`xlsx_invalid`）。Host 在 30s 后强制终止子进程，限制 IPC 合计为 20 MB（[convert-worker.ts](../../src/platform/convert-worker.ts)）；Node 的 V8 堆限制不覆盖外部 Buffer，故不能以 `Promise.race` 或 Worker 堆限制冒充内存沙箱。

## 5. 模型怎么「读懂」：列名 excerpt（已实现）

`kb_search` 契约不变：`path` / 行号 / `excerpt`。Skill 仍禁止用项目 `read` 冒充知识库。

实现位于 [search-excerpt.ts](../../src/formats/csv/server/search-excerpt.ts) 与 [search.ts](../../src/formats/csv/server/search.ts)：检索读取整份至多 20 MiB 的库内 CSV，按 RFC 4180 解析为逻辑记录并缓存「记录 ↔ 物理行范围」。CSV 不能在 clip **之后**按行拆字段：合法 CSV 允许引号中的逗号、分号、双引号和换行。

1. 剥 BOM；PapaParse（`papaparse@5.7.0`，表格编辑引入）负责 RFC 4180 拆字段，自研行扫描（`scanRecordRanges`）产出每条记录的物理起止行；两者记录数对不上时整文件失败（`csv_parse_invalid`）。**不要** `XLSX.read` 库内 csv，避免 `ID,` 走 SYLK、日期被改成序列。
2. 分隔符探测：扫描首条逻辑记录引号外的候选字符计数，取计数最高者；平局或均未出现按逗号处理。原方案设计的 `csv_parse_fallback` 未实现——歧义时静默按逗号解析，这是已知风险点；由于编辑保存后统一规范为逗号 CSV，偏差可被人工修正。
3. 命中定位所属逻辑记录后，file-detail 档取前后各 2 条记录组成窗口（`SEARCH_LIST_CONTEXT`）；相邻命中窗口按行合并去重，表头行不混入记录。`startLine` / `endLine` 仍回传原文件物理行号。
4. 表头行进文件级 `groupHeader` 字段（「列: 表头1 | 表头2 | …」），列表与明细档只在组头渲染一次，excerpt 记录行不再重复表头。
5. 字段中的换行显示为 `↩`，不改变库内原 CSV；字段数不一致时，缺的当空、多的按列序号补标签（`列N`）。

模型实际看到的（命中「乙公司」）：

```text
列: 供应商 | 金额 | 币种
供应商: 乙公司 | 金额: 98000 | 币种: CNY
```

工作台预览对 CSV 走表格形态（`EntryContentKind.Table`，[CsvGrid.tsx](../../src/formats/csv/client/CsvGrid.tsx)），不走 Markdown 编辑器；对话命中卡用改写后的 excerpt。

不要为了可读再落一份 `.md`。双份会重复命中、指纹乱。

## 6. 编码：把「请另存 UTF-8」做成 Host 的事（已实现）

CSV 侧实现位于 [decode.ts](../../src/formats/csv/server/decode.ts)：

| 优先级 | 判定 | 解码 |
|--------|------|------|
| 1 | `EF BB BF` | UTF-8，去掉 BOM |
| 2 | `FF FE` / `FE FF` | UTF-16 LE / BE |
| 3 | 整份是合法 UTF-8（允许裸 UTF-8 无 BOM） | UTF-8 |
| 4 | 否则 | 明确标记为「假定 GB18030」的严格解码 |

编码一律 `TextDecoder` + `{ fatal: true }`，避免替换字符掩盖损坏；Node 自带 `TextDecoder`，不引 `iconv-lite`。首次解码前探测 `gb18030` 是否可用：Node 的 small-ICU 构建可能不支持它，届时返回 `encoding_unsupported`，不能静默降级。第 4 步不是通用「侦测」：它只适合本产品的中国 Excel 范围，必须附 `encoding_assumed_gb18030` warning；其他遗留编码以后用用户明确选择的扩展，不可猜测。

解码后拒绝 NUL，控制字符只允许 tab 与换行，确保 ripgrep 不会把库内 CSV 当二进制。换行 `\r\n` / `\r` 收成 `\n`，再加 BOM 写出（[utf8.ts](../../src/formats/shared/utf8.ts)）：

```ts
const text = normalizeCsvNewlines(decoded.text)
const bytes = encodeUtf8CsvWithBom(text)
```

RFC 4180 解析使用 `papaparse@5.7.0`（表格编辑时引入的唯一解析依赖）；原方案「自写小型状态机」已被取代，但编码侧仍不引第三方库。

不要 `XLSX.read(decodedText, { type: 'string' })`：`read` 会按首字节猜 SYLK / HTML / DIF，默认还把 `00123`、日期、`=A1` 当 Excel 格子改掉。漏写 `type` 会把整段当 Base64。

Excel 默认 ANSI CSV 在中国常走第 4 步。无法解码、运行时不支持 GB18030、含 NUL/非法控制字符、单物理行超 64 KiB 或解出空文件：该项 `failed`，返回稳定错误码及通用文案，不回显原始异常。

## 7. XLSX：库门禁与「转出即可编辑」（已实现）

xlsx → CSV 用 SheetJS 的 `sheet_to_csv`。公共 npm 上的 `xlsx@0.18.5` 有已知安全问题，**禁止 `npm i xlsx`**。csv 源不进这个库。

选库门禁核验记录（2026-10-04，选型 `@e965/xlsx@0.20.3`，`--save-exact` 精确固定）：

| 门禁项 | 结果 |
|--------|------|
| 来源 / 发布者 | 第三方再发布（maintainer `e965`，发布仓库 `sheetjs-npm-publisher`），非 SheetJS 官方 npm 账号 |
| 内容一致性 | 与官方 `cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz` 逐字节比对：`xlsx.js`、`xlsx.mjs`、`LICENSE`、`types/` 全部一致（sha256 相同），确认未被篡改 |
| 安装脚本 | 无 preinstall / postinstall，包体 8 MB 为库本体，不是安装期下载器 |
| 版本固定 | `package.json` 精确锁 `0.20.3`；lockfile 记录 tarball sha512 integrity |
| 许可 | Apache-2.0 |
| 依赖树 | 零运行时依赖；仅打进 `lib/convert-xlsx-worker.js` 子进程 bundle，不进 `lib/index.js` |
| 审计 | `npm audit`（官方 registry）0 漏洞；0.20.3 已含 CVE-2023-30533、CVE-2024-22363 修复 |

| | 决定 |
|--|------|
| 读 xlsx | `XLSX.read(buf, { type: 'buffer', cellDates: false, cellStyles: true })`；不计算公式。若可导出单元格带 `f` 且没有缓存计算结果，则整份源失败，提示用户在 Excel 重新计算并保存（实测 SheetJS 0.20.3 对缺缓存公式产出桩单元格 `{ t: 'z', f, v: 0 }`：`v` 总是被物化，故以 `t === 'z'` 判定；不能用 falsy 检查，否则误判缓存值恰为 0 的公式）。缓存可能过期，程序无法证明其新鲜度，产品文案需要求用户计算并保存 |
| 写出 CSV | 先验证 `!ref` 声明范围未超过硬上限，再 `XLSX.utils.sheet_to_csv(ws, { FS: ',', RS: '\n', blankrows: false, skipHidden: true })` |
| 读用户 csv | **不调用**。走 §6 编码归一 |
| BOM | 库不写；两条源都由 `encodeUtf8CsvWithBom` 统一加 |
| 编辑同权 | 转出 CSV 落库即 `EntryFormat.Csv`，检索、表格预览、编辑、配额与手工导入完全同一路径；见 §4.1 |
| 隔离 | XLSX 库只进 `src/formats/xlsx/worker.ts` 子进程 bundle；30s 硬终止、20 MB IPC 兜底由 [convert-worker.ts](../../src/platform/convert-worker.ts) 统一执行 |

不要装：`node-xlsx`、`exceljs`、各种 `xlsx-to-csv`、officeparser / markitdown-ts / Python。

`.xls` / `.xlsm` / 加密工作簿：失败，提示另存为未加密 `.xlsx`。第一版不要开 SheetJS 的 `.xls` 路径。

XLSX 源级流程（已实现）：

1. 源体积 > 上限 → `file_too_large` 失败。
2. convert 抛错 → `failed`，返回稳定错误码（`xlsx_invalid` / `file_too_large` / `io_failed`）和通用文案。
3. 每个写出文件：`byteLength` 过 `min(maxFileBytes, 20 MiB)`（与库内 CSV 单文件上限一致）。
4. 目标名：xlsx 去 `.xlsx` 得产物名片段；sheet 名先映射成保守的文件名片段（清洗 `\/:*?"<>|` 与控制字符，空值回退 `sheet-<序号>`），再由 `ingest-output` 复验 basename 和处理冲突；不得直接把 sheet 名当路径。冲突仍 `name-2.csv`。
5. `sha256` 对写出 Buffer，不是源文件。
6. 临时写入 / rename / 回滚走 `ingest-output`，不 `copyFile` 源。
7. 一本 xlsx 写出多个 csv：每一份单独占一条 output 结果。**先算总字节再写**：任一产物超单文件上限或合计超库配额，整份 xlsx 失败、不落盘。

md 混在同一文件夹里：md 照旧拷；xlsx 走转换；失败项不挡同批。

## 12. 和 01 档的关系

01 定义通用 Converter、Host-only 与多输出事务。当前实现复用其安全原则：Host-only、输入边界、同一 Buffer 校验 / 写出、原子落盘和错误不回显；子进程隔离与限长 IPC 由 `convert-worker` 承担，多输出事务由 `import-service` 预检加 `ingest-output` 原子写共同保证。最终形态已落地：**xlsx → 经溯源审查且固定版本的 XLSX 库 → UTF-8+BOM 规范 CSV → 落库即可检索、即可表格编辑**；csv → 严格转码 + BOM CSV；均不生成 Markdown。

「模型读懂」靠检索改写 excerpt，不靠把表变成 md。编辑直接改库内这份 UTF-8 CSV，检索与 excerpt 随新指纹自然更新。
