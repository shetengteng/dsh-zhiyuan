# HTML 导入：HTML→Markdown 转换方案

> 日期：2026-10-06
> 序号：03（当日第三份；01 为测试目录的导入进度测试 Case，02 为 PDF 选型方案）
> 定位：给知源新增 `.html/.htm` 导入格式。HTML 页面不能原样入库（grep 与命中卡都吃不了 HTML），须在 Host 转成 Markdown 再走现有 ingest。
> 对照：[DOCX 方案](./2026-09-01-01-dsh-DOCX转Markdown方案.md)、[PDF 选型](./2026-10-06-02-dsh-PDF导入解析选型方案.md)、[XLSX 与 CSV 进库方案](./2026-09-02-03-dsh-XLSX与CSV进库方案.md)。
> 性质：库调研结论已与用户对齐（复用 `@joplin/turndown`）；**未对真实 HTML 样张跑过转换，不声称质量验收通过**。

---

## 1. 一句话

在 `src/formats/html/` 新增一个源格式模块：**隔离子进程**里按「BOM → meta charset → UTF-8 → GB18030 兜底」解码字节，用**已有的** `convertHtmlToMarkdown`（`@joplin/turndown` + GFM）把页面转成受控 Markdown，产物恒为 1 个 `.md` 条目，零新增 npm 依赖。

## 2. 现状与既有资产

- 当前导入白名单只有 `.md/.markdown/.txt`、`.csv`、`.docx`、`.xlsx`（[host-registry.ts](../../src/formats/host-registry.ts)），`.html/.htm` 未注册，导入报 `ext_denied`。
- **转换器已存在**：[html-output-policy.ts](../../src/formats/shared/html-output-policy.ts) 的 `convertHtmlToMarkdown`，内置 GFM 表格/删除线、链接协议 allowlist（只留 `https:`/`mailto:`）、剔除 `img/script/iframe/video` 等危险与媒体标签。当前唯一调用方是 DOCX worker，等于已在子进程 bundle 里验证过。
- **依赖已就位**：`@joplin/turndown@4.0.86` 自带 `@mixmark-io/domino` 纯 JS HTML 解析器，**不需要 jsdom、无原生模块**（已核实其 package.json dependencies）。
- **子进程基建已就位**：`runIsolatedConversion`（convert-worker.ts）+ esbuild worker 打包，DOCX/XLSX 同模式。
- **字符集解码有先例**：CSV 侧已有「BOM → UTF-8 → GB18030 兜底」实现（csv/server/decode.ts），含 gb18030 可用性探测。

## 3. 选型结论

| 候选 | 结论 | 理由 |
|------|------|------|
| `@joplin/turndown` 4.0.86 | **复用（零新增）** | Joplin 团队活跃维护；domino 纯 JS 解析无 jsdom；与 DOCX 路径同一条管线，库内 Markdown 风格统一；链接 allowlist 等安全设计已落地 |
| `turndown` 原版 | 不装 | 维护基本停滞；Node 下需 jsdom（重且有安全通告史） |
| `node-html-markdown` | 不装 | 扩展点少，写不了链接 allowlist 这类规则；9 个月未发布 |
| `rehype-remark`（unified） | 不装 | 链路长、依赖重，为单一转换引入整套 AST 生态不值 |
| Pandoc | 排除 | Haskell 二进制，无法随插件打包 |

## 4. 设计

### 4.1 格式注册

- `content-contract.ts` 新增 `SourceFormat.Html = 'html'`。
- 新模块 `src/formats/html/html-format.ts`：`sourceExtensions: ['.html', '.htm']`；产物恒为 1 个 Markdown 条目，**无 entryHandler**（与 DOCX 完全一致——落库后就是普通 `.md`，预览/编辑/检索全部免费复用）。
- `host-registry.ts` 的 `CONTENT_FORMAT_MODULES` 数组加一项即可，路由与扩展名白名单自动生效（文件选择 filter、`ext_denied` 文案都是动态生成）。

### 4.2 执行位置：隔离子进程

与 DOCX/XLSX 同模式，新增 `convert-html-worker.js` 子进程入口，理由：

1. HTML 是**不可信外部输入**，domino 解析畸形/恶意页面（超深嵌套、超大属性）时的异常与内存行为不应影响 Host；
2. 5 MiB 级页面的解析与转换是 CPU 密集操作，进程内跑会阻塞 Host 事件循环，拖累并发 RPC；
3. 失败路径清晰：子进程崩溃 = 转换失败，报 `io_failed`，不污染 Host 状态。

协议沿用现有帧格式：`diagnostic / output / done / failed`，请求校验用独立 `html-request.ts`（`kind: 'convert-html'`），与 `docx-request.ts` 同构。

### 4.3 字符集解码（新增 `server/charset.ts`）

HTML 老页面常见 GBK/GB2312，解码顺序：

1. **BOM**：UTF-8 / UTF-16LE / UTF-16BE 直接判定；
2. **meta 声明嗅探**：无 BOM 时取前 2KB 按 latin1 读，匹配 `<meta charset="...">` 或 `http-equiv="Content-Type"` 里的 `charset=`（meta 必须出现在前 1024 字节，2KB 覆盖足够；标签字节本身在任何常见编码下都是 ASCII）；
3. 声明的 label 能被 `TextDecoder` 接受就用它（try/catch 探测，与 CSV 侧 gb18030 探测同思路）；
4. 都没有 → UTF-8；UTF-8 严格解码失败 → GB18030 兜底（GB18030 向下兼容 GBK/GB2312）。

产物统一 UTF-8。`fatal: true` 的解码错误转为 `io_failed` 并给人话文案。

### 4.4 转换策略

直接调用现有 `convertHtmlToMarkdown`，语义要点：

- `<head>`、`<script>`、`<style>` 无文本产出，自然消失；`img/iframe/video` 等被显式规则剔除；
- **相对链接自动降级**：策略规定无 scheme 的 href 只保留链接文字——HTML 导入场景正合适（链接目标文件不在库里，保留 href 反而制造死链），无需处理 `<base href>`；
- 锚点 `#foo`、`javascript:` 等同样被 allowlist 丢弃；
- `droppedLinkCount > 0` 时回传 diagnostic：`已移除 N 个不允许保留的链接`（与 DOCX 一致）；
- 导航栏、页脚等页面噪音**第一版保留**（正文抽取是明确的非目标，见 §7），只剔除标签级噪音。

不做 `<title>` 提取：很多页面 title 是站点名+SEO 垃圾，误提会污染条目命名；条目名沿用源文件名。

### 4.5 命名与限额

- `foo.html` / `foo.htm` → `foo.md`（与 DOCX 命名规则一致）；
- 源文件过 `maxFileBytes`（默认 5 MiB），转换产物再过一遍；超限报 `file_too_large`；
- 同名 `.md` 条目已存在时走现有 ingest 的去重/跳过逻辑，本模块不感知。

### 4.6 Client 影响面（仅静态文案）

- [ImportDialog.tsx](../../src/view/settings/dialogs/ImportDialog.tsx:107)：help 文案追加 html/htm 支持说明；
- [AboutPage.tsx](../../src/view/settings/AboutPage.tsx:24)：支持格式清单同步。

文件选择 filter、错误提示由 Host 动态生成，无需改动。

## 6. 测试计划

单测（`src/formats/html/` 下 `.test.ts`）：

- charset：UTF-8 无 BOM / UTF-8 BOM / UTF-16 BOM / GBK 无 BOM+meta 声明 / GBK 无声明兜底 / 声明未知 label 回落；
- 转换：标题/列表/表格/围栏代码映射正确；`script` 内容不出现；`https` 链接保留、相对链接只留文字；`<title>` 不混入正文；
- 请求校验：非 `convert-html` kind 拒绝；超限拒绝。

fixtures：中文 UTF-8 页面、GBK 老页面、含表格与代码的文档型页面、含 script/iframe 的恶意页面。

## 7. 非目标（第一档明确不做）

- **正文抽取**（Readability / Defuddle 剔除导航页脚）——等真实样张反馈后再立项；
- 图片下载/内联 base64（同 DOCX：图片进不了 grep，且顶配额）；
- 相对链接改写为绝对地址；
- frameset / JS 渲染内容（导入的是静态 HTML 文件，不做浏览器渲染）；
- Markdown 内嵌原始 HTML 的白名单通道（一律转纯 Markdown，转不出的丢文本）。
