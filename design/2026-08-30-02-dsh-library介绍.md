# 社区插件介绍：dsh-library（本机文档库）

> 日期：2026-08-30  
> 序号：02（同日 01 是可行性方案）  
> 对象：PerryLink 做的 DeepSeek Harness 插件 **dsh-library**  
> 定位：把电脑上的 md/txt 变成能问的知识库；默认不下载模型、不联网搜索。

## 1. 一句话

你告诉它本机某个 md/txt 的路径，它切成小段、做成能搜的目录，DSH 里的 AI 就可以问「规范里重试怎么写的」，并标出出处。

社区里它最接近我们要的「阶段 1 本机知识库」。但只有对话工具，没有设置页，不能传 PDF，也没有云端 API。

---

## 2. 在 DSH 里长什么样

这是装在 DSH 主进程上的插件（Web 版也可以一起装）。人几乎不点界面：AI 调工具干活，你可以用斜杠命令看每个库有多少篇。没有独立设置页，也没有网盘式上传。

```text
电脑上的 md/txt
    │  工具：library_add（只收文件路径，不收浏览器拖进去的字节）
    │  按 DSH 的文件权限去读
    ▼
切成小段 → 做成搜索用的数字（默认按字凑；也可接本机 Ollama 或外部命令）
    │
    ▼
存在 DSH 给插件用的小仓库「dsh_library」里
    文档清单 / 小段 / 删除记录
    │
    ▼
library_search：按字和按意思一起打分
    → 去掉太弱的、打散重复的、把最相关的放在首尾
    → 带 [1][2] 的结果页
    │
    └─ 选择注入对话时，当前 AI 能看见这页，并记一条审计
```

兼容：DeepSeek Harness `0.1.1-rc.2`；Node `^22.19 || >=24`；许可证 Apache-2.0。

---

## 3. 能做什么

### 3.1 工具和命令

| 名称 | 人话 |
|------|------|
| `library_add` | 按路径导入一篇。要告诉它路径和库名。不能从网页直接丢文件进来。 |
| `library_remove` | 删掉后还会抽查：被删内容的痕迹还在不在索引里，有残留会告诉你。 |
| `library_list` | 只列有哪些文档，**不把正文塞给模型**。 |
| `library_search` | 搜索。可以要求把结果页写进当前对话。 |
| `library_cite_check` | 核对答案里的 `[1]` `[2]` 是不是真能对上这一次搜到的段落。 |
| `library_diagnose` | 看切片大小、是不是有近重复、自己搜自己能不能中。 |
| `/library [名字]` | 每个库一行摘要：多少篇、多少段。 |

典型说法：

```
把 ./docs/spec.md 加入 docs 知识库，然后回答：规范里关于重试是怎么说的？用 [n] 标记引用。
```

### 3.2 搜索为什么不只「找最像的一段」

这是它比「向量一搜就完」强的地方：

1. 按意思和按字混着打分（默认更偏一点意思那路，但字也对得上）。  
2. 避免十条结果都是同一段换了个说法。  
3. 太不像的丢掉。  
4. 最有用的几段放在结果页的开头和结尾——模型读长文时，中间容易忘。  
5. 核对引用时，只认这一次结果页上的 `[n]`，不认模型随口说的「张三 2024」。

自研的时候，**质量管线值得对照**，不必从零发明「搜完就丢给模型」。

### 3.3 离线到什么程度

可行性方案里把「离线」拆成两层。这个插件只保证第一层：

| | 它怎么做 |
|--|----------|
| **知识库离线** | 默认用 hash：按字凑出一串数字，不下载模型、不联网。目录存在 DSH 本机仓库里。 |
| **聊天模型离线** | 不管。回答仍用你当前 DSH 配的模型。拔网线还能不能写成文章，取决于你有没有本地大模型。 |
| **可选：真的懂意思** | 可接到本机 Ollama（默认本机 11434 端口、`nomic-embed-text`）。连不上就退回 hash。也可以指定一条外部命令，不走系统 shell。 |

权限：只读你让它导入的那些文件；只写自己的 `dsh_library` 小仓库。文件路径和那串数字 **不写进聊天记录**。审计只有「注入过结果页」「删除时查过残留」。

hash 为什么弱、小库能不能改用「换词再查找」，见 07。

## 4. 安装

```sh
dsh plugin --profile web add dsh-library
# 或跟仓库最新：
dsh plugin --profile web add "github:PerryLink/dsh-library#main"

dsh --profile web --dump-config   # 里应出现 id: dsh-library
dsh web
```

卸掉：`dsh plugin --profile web remove dsh-library`。

如果 pnpm 拦住了 esbuild 的安装脚本，按命令行提示，在这个 profile 的 `pnpm-workspace.yaml` 里允许 esbuild 构建即可。

另外还有 `dsh1024` 商店渠道，和官方 `dsh plugin add` 是平行的，用来上排行榜，运行不依赖它。

## 5. 配置（摘常用的）

这些是插件配置行里的字段。**按插件 id 覆盖时是整行替换**：改一个键，其余键也要重新写上。

| 键 | 默认 | 人话 |
|----|------|------|
| `chunkSize` / `chunkOverlap` | 900 / 120 | 一段多长、相邻两段重叠多少个字 |
| `maxFileBytes` | 5 MiB | 超过这个大小，导入直接拒绝 |
| `embedding.provider` | `hash` | `hash`（按字凑）/ `command`（外部命令）/ `ollama`（本机模型） |
| `search.topK` | 8 | 最后留给模型几段 |
| `search.maxResultChars` | 16000 | 结果页最多多少字 |
| `injection.maxChars` | 12000 | 写进对话时的字数上限 |

完整表看上游 README。不要把这些抄进「产品设置页」文档——上游 **没有** 给人点的设置界面。

## 6. 明确做不到的

- 只认 md/txt。PDF、Word 抽不了。  
- 必须给电脑上的路径，没有选文件夹面板，也不能网页选文件上传。  
- 默认 hash 是「字长得像」，换个说法就弱。要懂意思，自己接 Ollama 或外部模型。  
- 核对引用只看 `[n]` 对不对应当次搜到的段落，不核对「《某某规范》第三节」这种自由写法。  
- 不是网盘，不是云：不能上传到服务器、没有多人账号、没有自己的云 API。

## 7. 和我们要做的差在哪

| 我们想要的 | dsh-library | 结论 |
|------------|-------------|------|
| 本机断网还能搜 | 已经做到 | **可以先装来试用**，把「给路径 → 对话里问」跑通 |
| 给人点的管理页、上传 | 没有 | 还得自己做设置页 |
| 好几种库、好几种文件 | 只有文档库、一种切法 | 接口要自己设计 |
| 以后接自己的云 | 没有 | 不能拿它当云客户端 |
| 搜索质量手法 | 混合打分、打散重复、核对引用、删除抽查 | **对照着做**，不要做成「搜到就完」 |

**建议**：动手写自己的插件之前，先 `add dsh-library` 用几天真文档，看看 DSH 里 AI 怎么调工具、怎么标引用。自研时对照它的搜索质量，不要把这个包装进仓库当运行时依赖。
